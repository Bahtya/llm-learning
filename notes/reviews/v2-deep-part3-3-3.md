## A. 最严重 5 问题（按影响排序）

**A1（核心问题级）贯穿案例的归因前后矛盾，核心问题"换引擎差一倍"缺少证据且未声明缺口。** 开篇说"卡不变、模型不变、档位不变，单并发吐字从约 50 做到 80~100——靠的是一个社区调优的运行时项目"；到贯穿案例分析（134 行）又说"50 到 100 之间最大的一截来自 MTP……引擎层的三板斧负责不浪费"。同一章先归因给引擎、再亲手推翻。更深处：全书没有任何"同一张卡、两个引擎、同口径对照"的数据（v3/07 的"速度差好几倍"同样是设问而非证据），"差一倍"实际是社区体感加 vLLM 论文"利用率两到四成→并发容量差数倍"的拼合量级。读者带着"换引擎=快一倍"的预期离开本章，做 3.4 对照实验时大概率发现差不到一倍，反而怀疑自己测错。策略：开篇就把 50→100 的大头挑明是 MTP（ gloss 顺势解决 MTP 首现未释）；给核心问题立"量级判断、无对照数据"的口径声明；终分析用 2.2 已有的天花板账把归位做实——裸 decode 50 贴着"双卡聚合 ÷ 权重"的 55~60 上限（引擎的真实功劳=贴着天花板跑），MTP 后的 100 超上限（一次前向吐多 token，天花板被挪走）。

**A2（数字口径级）完整算例与已解示例用"含 MTP 的 100 tok/s"按"每 token 一次前向"算发射占比。** MTP（多 token 预测）一次前向吐多个 token，"每吐一个 token 完整跑一遍前向"的前提不成立，每 token 摊到的前向次数小于 1，25% 是被高估的数字；且"CUDA Graph 消发射开销"与"MTP 减少 token 间发射次数"两个机制被混在一本账里，读者无从分辨哪一笔是 Graph 赎回的。此病继承自源章 v3/05，属"原资料如此"但教材应当修正而非照搬。策略：算例改双口径并列——裸 decode 50 tok/s（20ms 预算、12.5%，常态口径）与含 MTP 100 tok/s（10ms、25%，显式标为上限口径），公式区加一行"MTP 修正"，误差来源补"前向次数未实测"。规格"500×5µs=2.5ms vs 10ms 预算"的算例锚点原样保留，只加条件不换题。

**A3（任务失败级）毫秒分解表两行循环定义，承诺产出实际填不出来。** "连接与前期处理"的测法是"TTFT 减去 prefill"（残差），"prefill"的测法是"首字时间减去前期段"——两行互为余数，没有一个独立锚点，读者代入自己的 curl 数字会陷入"先有鸡还是先有蛋"。这张表是本章承诺产出、也是 3.4 明言的输入数据。策略：定测量次序——prefill 用"输入 token 数 ÷ PP"独立估算（PP 来自服务端 timings 字段或 llama-bench，3.1 已教）；前期段做残差；TPOT 分母按 3.1 的"输出 token 数 − 1"口径统一（原表是"÷ 输出 token 数"，跨章不一致）；补一行可直接粘贴的 curl -w 模板（源章 v3/08 有，本章丢了）。

**A4（纪律级）时效标注与措辞越界四处。** ①"运行一个多月迭代到 v0.1.12，GitHub 300 star"是 BV14yT46kE5T 时点的快照数据（笔记明言项目仍在迭代），正文写成现在时；②"启动日志里的 attention backend 一栏就是在选它（FlashInfer）"过强——vLLM 各版本默认后端不同，源章 v3/07 的原文是"如 FLASHINFER / FLASH_ATTN"举例；③实验预期"显存高一块（几百 MB 量级起……）"是无来源数字，违反"不得新增无来源数字"；④eager 模式被注为"不建图、逐个发射的默认模式"——默认恰是建图，读者会以为开关无效。附带一处条件丢失：CMP 90HX"至少三张卡"的源素材条件是"跑 27B 的 FP4 级权重"。策略：全部加时点/例举/去数字化处理，eager 释义改正。

**A5（跨章口径与出处级）五处小口径不齐与一处出处缺失。** ①"128KB…4GB"与 3.2 立下的"账按 KiB/GiB"规矩冲突（3.2 同一笔账写作 128 KiB/4 GiB）；②"千问 27B"未对齐 3.1 已定的"千问 3.6 27B（口播转写型号，以模型卡为准）"全称口径；③i3-9100T/双通道内存出自 BV12ZEN6CEho（v3/08 的引用），来源清单五组里没有它；④能力清单"解释三件事……（排队一节 + 理解检查 4）"映射错误——理解检查 4 是 CUDA Graph 选型题；⑤32 路小练习没有给每步预算的代入口径，"算一算"无法执行。策略：单位统一为 KiB/GiB、型号对齐、来源补列、清单重挂、练习补"每步前向约 30ms（示意值；用你 3.2 压测数据更好）"。

## C. 缺失的前置解释 / 算例 / 反例 / 实验条件 / 来源

1. **MTP 首现 gloss**（术语）：开篇连用两次才在贯穿案例展开；补"（多 token 预测，一种投机解码，3.5）"。
2. **"差一倍"的口径声明**（反例/条件）：无同卡双引擎对照数据这一事实必须写明，否则读者把量级判断当实测结论带走。
3. **天花板对照账**（算例，贯穿案例）：2.2 已算出的"双卡聚合 55~60 tok/s 上限"是本章唯一能把 50/100 归位的锚点，原章未用——补上后"引擎的功劳"才有独立证据，不与 MTP 混账。
4. **MTP 修正行与第五条误差来源**（算例条件）：开 MTP 时每 token 前向次数 <1，占比为上限口径——规格算例锚点（10ms 预算）保留的前提下补条件。
5. **毫秒分解的独立锚点**（实验条件）：prefill=输入÷PP 必须先行，前期段才可做残差；PP 的取数位置（服务端 timings / llama-bench）需写明。
6. **curl -w 模板**（实验条件）：源章 v3/08 有完整命令，本章丢掉了；表下补回，"不点链接能懂、照抄能跑"。
7. **CMP 90HX 释义与 FP4 级条件**（术语+条件）：源章 v3/05 的括号注释在转写中丢失。
8. **i3-9100T 的来源 BV12ZEN6CEho**（来源）：事实在、出处缺。
9. **eager 模式的正名**（实验条件）：eager=不建图、逐个发射的**非默认**模式；"Capturing CUDA graphs"日志措辞加"随版本变"。
10. **32 路小练习的代入口径**（算例）：补示意值 30ms 并邀请代入 3.2 实测。
11. **反例已有，不必新增**：W8A8"格式对、内核缺、快不起来"是现成的格式决定论反例；开关表第三、四行是发射开销不起作用的反例。所有修订数字（12.5%、55~60、30ms 示意值）均由章内与在书口径推出，无新增无来源实测值。
