# v2 评审 · 后端开发

评审身份：会 Python 的后端开发，未接触过大模型推理、显卡、量化。逐章 Read 全部 23 章（part1~part5，按章号顺序），只评可懂性三维（术语先用后讲 / 逻辑跳跃 / 章间衔接）与章末产出链，不评代码、不评 assets、不评知识正确性。

## 总评（能否按此书学会？主线是否成立？）

**能学会，主线完全成立。** 以零基础后端的身份按顺序读完，主线"部署→链路→显存→测量→瓶颈→量化并行→多用户→选型成本"与章序严格对应，没有出现讲不下去的地方。三点突出优点：

1. **章间衔接是我读过的技术书里最严的**：逐处核对了 22 个"与下一章的衔接"承诺，除 2.1 一处向后指错卷外全部兑现（1.2→1.3 KV、1.4→1.5 总参/激活参、2.5→3.1 指标转正、3.5→4.1 TP/PP、4.4→5.3 TCO 引用 T6 等）。
2. **公式与算例全部跟得上**：抽查了 20 多处算术（KV 公式 128 KiB/144 KiB、超级块 144 字节→4.5bit、带宽 352×14÷8=616GB/s、pp 流水 8 拍对 5 拍、η 不等式 η>0.83×电价、10 次测量均值 440.2÷10 等），单位推导、数量级检查、口径声明齐备，作为后端读起来非常踏实，没有一处"步骤跟不上"。全书没有发现失效的类比（前台后厨、摘录卡、全科门诊 vs 专家、抄书、递菜单、买车打车都划了边界）。
3. **项目闭环真实存在**：T1 选型一页纸(1.5)→T2 显存计算器(2.1)→位段笔记(2.3)→GGUF 走查单(2.4)→T5 量化对比(2.5)→个人指标表(3.1)→并发表(3.2)→时延分解表(3.3)→T3+T4 性能报告(3.4)→MTP 决策记录(3.5)→互联笔记(4.2)→T6 压测报告(4.4)→T8 规格表模板(5.1)→天梯表(5.2)→T7 成本决策书(5.3)，最后 5.4 装订成"期末答卷"。后件确实引用前件（5.3 用 T6 的负载、5.2 用 T8），不是摆设。

**会卡住的四个环节**（按卡人程度排序）：

- **token 计数方法错位**：1.1 能力清单承诺"数出一个句子的 token 数"，但全书教数 token 的方法（usage 字段、"一字一 token"粗估）在 1.4 才出现；1.3 实验又引用"第一章的分词口径"。这是产出链上唯一"承诺了却给不出"的环节（见问题 1、5）。
- **3.3 的环境断崖**：全书从 Ollama(11434) 起步，3.1 脚本突然是 8080+模型名 "local"，3.3 实验直接要求"已装好 vLLM"。产出（时延分解表）虽可用 curl 兜底完成，但 CUDA Graph A/B 实验对跟随 Ollama 路线的读者等于不可做（见问题 18、19）。
- **交付物编号乱序**：T 编号与阅读顺序错位（T5 在 T3/T4 之前出现、T8 在 T7 之前），读者在 5.4 之前无法用编号自检攒齐了没有（见问题 20）。
- **硬件不可复现有兜底**：贯穿案例的双 22G 卡/27B/256K 大多数读者没有，但各章都给了"纸面复算"替代路径，这个处理是诚实的，不构成卡点。

按此书顺序读完并做完产出，可以独立完成"给团队部署一个可承受 N 人并发的本地推理服务并回答值不值"——这正是开篇的任务。
