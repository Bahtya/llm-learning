评审对象：`/data/data/com.termux/files/home/project/llm/content/` v1~v6 共 46 章，按卷章顺序全部读完。本轮只抓"数字与口径的最终一致性"，不评代码。

## 验收结论（有条件通过）

理由：**全部点名核对的数字账都经得起复算**。我把书中每一条可算的账都重新推导了一遍，包括：

- **44G 三本账**：44G = 2×22G = 20G 权重（AWQ INT4）+ 16G KV（256K、FP16）+ 约 8G 缓冲区。出现在 v1/05、v1/06、v1/08、v2/03、v3/04、v4/02、v5/01、v5/02、v6/01 九处，拆法与"绰绰有余"原话处处一致；v3/04 的并发推演（2 路并发 KV 翻倍到 32G → 52G > 44G OOM）自洽。
- **KV 64G→16G**：64×8×128×2×262144×2 B = 64 GiB（naive），1/4 全注意力层 → 16 GiB；Gemma 10/60 层 → 120G→20G。v1/05、v1/06、v1/08、v4/02、v5/02、v6/01 六处口径统一，且"naive vs 修正"的标签没有一处丢。v2/06 的三档账（FP16 64G / INT8 32G / Q4 16G）是同一公式的正确推论。
- **27B 权重三口径**：v4/02 的对照表（理论 54G / 13.5G，Q4_K_M 文件 16.5G，AWQ 实测 20 多 G）与 v2/02（54G/27G/13.5G）、v2/03（27G 理论 vs 30 多 G 实测）、v2/05（54GB/13.5GB）、v4/03、v4/06（16.5G Q4_K_M）逐处对得上，且"四口径并存、引用必注"的纪律执行到位。
- **裸 decode 50**：v1/08、v3/01、v3/03、v4/07、v5/01 五处均为"裸约 50 / 开 MTP 100 / Prefill 1700"，与"最高速度≠稳定复现"的声明绑定出现。
- **864 万 token/天**：100 tok/s × 86400 s = 8 640 000，v4/09、v5/07、v6/01 三处一致，且都标了"含 MTP 的峰值口径"；电费 14.4 度→十几到 20 元→对比 API 1000 万 token 的链条闭合。
- **V100 130T 口径**：v3/07（口播 130T；官方 112~125T）、v4/04（PCIe 112T、SXM2 125T）、v5/04（125T/112T）三处同口径，没有把口播值当官方值。
- **170HX 31 倍 / 100 TOPS**：v2/01、v4/05、v4/10 三处都写了同一句免责——31 倍只属 FP32 那行（0.3×31≈9.3 TFLOPS），100 TOPS 是另一张表（TF32）的数，且 v4/05 还补了 A100 TF32 156 TFLOPS 的官方锚点防误比。
- **90HX GDDR6X**：v4/05（10G 320bit ≈760 GB/s，320×19÷8 复算成立）、v5/04（GA102+GDDR6X，同一数字）一致。
- **修复稳定性**：CUDA 13/图灵（v3/09"2080S 支持 CUDA 13" + v4/04"图灵是 CUDA 13 仍支持的最低架构，停在 12 的是 Volta/Pascal" + v3/02、v5/04 的 V100 停 CUDA 12）四处同向；90HX PCIe 方向（出厂锁 1.0 x4 → 解锁到 x16≈3.0 x8，170HX 始终 1.0 x4）在 v4/06、v4/07、v4/10 三处一致；"推理"定义只在 v1/01 出现一次，无第二定义竞争。
- **全书内部链接**：46 章互链 0 断链、46 章全部被引用，术语表路标可用。
- 其余抽查复算全部通过：softmax 三档温度表、170HX 带宽乘式、TP all-reduce 129 次/5.4GB/87GB/1.65 万次、PP payload 20MB/10KB、PagedAttention 8B 模型 128KB/token 与 4GB/请求、CUDA Graph 10ms/2.5ms/四分之一、6.13 万亿÷150 亿≈409、2e9÷86400≈2.3 万/s、312 元/GB、176B 的 3.3 bit/1.3 bit、scale 开销 3%、FP16 上界 65520 溢出说明等。

**未通过的原因只剩两类**：v6/03 出处表有一批"章节指错了"的硬错误（读者按表去找会扑空），以及一处两章之间的"decode 理论上限"没有互相解释（正是"读者会停下来怀疑自己"的点）。数字本身没有发现一处错账。

## 遗留问题清单

1. **（高）v6/03 出处表 5 行的"主要引用章"指到了没有引用该视频的章**。逐个 BV 号 grep 全书核对，实际引用关系与表格不符的有：
   - `BV1QC7Q61E3T`（3500 块 FP8 80tok/s）表列 "v5/01、v2/02"——该 BV 只出现在 v5/01，v2/02 里 0 次；
   - `BV14yT46kE5T`（20 系支持 FP8/NVFP4）表列 "v2/01、v2/02、v3/07、v4/04"——v2/02 里 0 次（实际另见 v2/04、v2/05、v3/05）；
   - `BV1YxjU6qEuw`（显存比显卡贵）表列 "v4/03、v4/06、v4/10"——v4/06 里 0 次（实际另见 v1/03、v1/07、v3/01、v3/04、v4/01、v4/05）；
   - `BV1GtbL63Ekt`（入坑心法）表列 "v1/10、v3/02、v6/01"——v6/01 里 0 次（实际另见 v2/04、v2/06、v4/08）；
   - `BV1i6Y86AEv3`（3000~1 万不推荐）表列 "v5/04、v4/02、v6/01"——v6/01 里 0 次（实际另见 v1/04、v1/05、v2/06、v3/04、v4/03）。
   5/22 行（23%）含无效条目。这张表的全部价值就是"按 BV 号查证 + 按章找案例"，建议逐行重跑一次引用扫描后重写该列。
2. **（中）"decode 理论上限"两章各说一个数，没有互相解释**。v1/08 与 v5/01 写"裸 decode 约 50 tok/s，带宽理论上限约 60"；v4/03 写"2080Ti 带宽 616 GB/s ÷ 16.5 GB ≈ 37 tok/s 理论上限，实测一般打六到八折"。读者按 v4/03 的公式算会得到"理论 37、实测应为 22~30"，而前文实测是 50——比"理论上限"还高，必然停下来怀疑自己。实际 reconcile 的钥匙书里是有的：v5/01"两张 2080Ti 合计约 1.2TB/s ÷ 20 多 G ≈ 60"（双卡 TP 聚合带宽 + AWQ 20 多 G 权重），v4/06 也写了"TP 等效显存带宽翻倍"。缺的只是 v4/03 或 v1/08 的一句注："37 是单卡 Q4_K_M 口径；该方案是双卡 TP，聚合带宽 1.2TB/s、权重 20 多 G，故上限约 60"。建议补一句，否则这是全书唯一一处"实测 > 书中给出的理论上限"。
3. **（低）术语表路标错一格**：v6/02 "基线（baseline）→ 投机解码(v3/06)"，但 "baseline/基线" 全书只出现在 v3/01 和 v4/07，v3/06 里没有这个词。应改指 v3/01。
4. **（低）同一术语两章不同名**：v5/07 定义 "TCO（Total Cost of Ownership，总拥有成本）"，v6/02 词条写 "TCO（总持有成本）"。最终版建议统一为"总拥有成本"。
5. **（低）术语表漏收正文反复使用、且给过正式定义的词条**：ECC（v4/05 整节 + v5/04）、GQA（v1/05 专节、v3/03 复用）、反分词/detokenize（v1/01 定义、v1/02、v3/03、v3/08 复用）、加速比（v3/06、v5/03，含两个公式）、抽样偏差（v5/08、v6/01，属"方法论黑话"表却缺席）、良率/刀法/矿潮（v4/10 定义、v4/04、v5/04、v5/07 复用）。词条末尾那句"搜不到的词，多半在别章的英文原词下"盖不住这几个中文原词。
6. **（低）v1/06 验证小节 "增量 ≈ 16G × (64K−4K)/256K ≈ 3.7G"**：精确值 3.75G（按 K=1024 算），写 "≈3.8G" 或 "3.7~3.8G" 更稳。末位数字类，量级无碍。
7. **（低）v2/02 "8 位一共只有 256 种组合，所以 FP8 能表示的数只有 256 个；FP16 有 65536 个"**：严格说位型里还有 NaN/Inf 编码（E5M2 有限数值 250 个、E4M3 变体更少），"组合数=可表示数"是教学简化。对本书读者可以接受，但可加半句"（忽略 NaN/Inf 等特殊编码）"以免较真的读者卡住。
8. **（低）FP8 Prefill 数字口径漂移**：v1/07 与 v3/09 写 "1600–1700 tok/s"，v5/01 速度表写 "约 1600 tok/s"。同一实测建议统一为 "1600~1700（表中记 1600+）"。
9. **（低）Volta 支持的表述有内在张力**：v3/02 说"如今的新版（V1 引擎）不再官方支持 Volta"，v3/09 引原话"从来没有被 vLLM 类高性能框架正式官方支持过"。"不再支持"与"从未支持"是两个命题，两章都同时保留了两种说法。建议在 v3/02 加半句区分（"引擎层面曾短暂支持、V1 起移除；UP 主口播强调的是从未一等公民"）。
10. **（低）v6/03 头部说明与表内标注略冲突**："22 期里 21 期进入正文（另 1 期仅作背景提及）"，但 `BV1dtgf6pEbW` 行标的是"未入正文"，且全书正文（v6/03 之外）确实 0 次引用。建议改成"21 期进入正文，1 期未入正文（其'多卡堆显存'的提法在 v4/08、v5/06 另述）"。另外该期表列漏了 `BV1nVVr6QEFq` 的 v1/08——那是"裸 decode 50"这个全书锚点数字的出处章，值得补上。

## 结语

第 1 项验收（跨章数字账）全部通过，且比上一轮更干净：所有"同名同账"的数字都能从公式重新推出来，naive/修正、口播/官方、含 MTP/裸跑这几组最容易混的口径在每一处都带着标签。第 2 项验收（修复稳定性）四项里三项完全稳定，只有 v6/03 出处表自身带伤。第 3 项（残留卡点）只剩第 2 条这一处真正会让人停下来的，其余是末位数字与词条级收尾。修掉第 1、2 条即可放行。
