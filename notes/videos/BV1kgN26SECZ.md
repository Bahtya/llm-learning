# BV1kgN26SECZ 揭穿"OpenRouter 周调用量世界第一"：小样本榜单 ≠ 真实调用量

> 视频时长约 1 分 09 秒（37 段字幕）。UP 主针对媒体常引用的"某模型在 OpenRouter 上周调用量世界第一"说法做量化拆穿：OpenRouter 只是一个国外的 API 中转/聚合平台，样本量极小，理论上仅需约 400 个重度 API 用户就能把任意模型刷上周榜第一。
>
> 转写勘误对照：open RT / open router → OpenRouter；Cloud → Claude；Cloud code → Claude Code；头根 → 拢共（总共）；2000000000 token → 单日 20 亿 token；抹去下名字 → 抹去一下名字。

## 术语穷举

- **调用量**：一段时间内模型被使用的 token 总量，本视频的核心争议指标——"过去一周他调用量是 6.13 万亿 token"
- **OpenRouter**（字幕误写"open router""open RT"）：一个国外的 API 中转/聚合平台，被媒体当作权威数据源引用——"你乍一看以为他是一个很权威的机构是吧，错误，它就是一个 API 中转站"
- **API 中转站**：转发/聚合各家模型请求的中间商，其数据只反映自家小样本——"它是一个国外的 API 中转站，它的调用量小到什么程度呢"
- **API**：应用程序接口，此处指按 token 计量付费的模型调用方式——"我是一个中度偏重度的这样一个 API 的用户"
- **API 用户**：直接调用模型接口（而非网页聊天）的人，消耗量级远大于普通用户——"中度偏重度的 API 用户……最多的一次每一天可以用到 20 亿 token"
- **token**：大模型计费与用量统计的最小文本单位——"拢共 6.13 万亿 token"
- **周榜 / "世界第一模型"**：OpenRouter 按周统计的模型调用量排名——"这是在过去一周世界第一模型啊"
- **刷榜**：用少量大用量用户的人为流量抬高榜单排名——"如果说你想要在这个地方去刷榜的话，你最少的话你只需要 400 个我"
- **数量级估算（亿 / 万亿）**：用个人用量反推榜单所需人数的方法——"6.13 万亿 ÷ 150 亿 ≈ 400 个我"
- **Claude**（字幕误写"Cloud"）：Anthropic 的主流模型系列——"现在最火的模型是什么？Claude、GPT、Codex"
- **GPT**：OpenAI 的模型系列——"Claude、GPT、Codex"
- **Codex**：OpenAI 的编码模型/编程 Agent——"Claude、GPT、Codex"
- **Claude Code**（字幕误写"Cloud code"）：Anthropic 的命令行编程 Agent——"Cloud code，这些用户量都是几百万级的"
- **用户量级（几百万级）**：用活跃用户数量衡量产品真实规模的口径——"这些用户量都是几百万级的用户"
- **榜单数据引用 / 权威性错觉**：媒体把第三方平台小样本数据当成"世界第一"的权威依据——"因为他引用的一个数据叫 OpenRouter"
- **抹名处理**：UP 主故意隐去模型名以避免争议——"我们先抹去一下名字，避免一些不必要的争议"

## 论断清单

- "某模型周调用量世界第一"的说法不可信，不能证明模型真实地位 | 经验圈子信息 + 量化估算 | "调用量世界第一，假的，全部都是假的"
- OpenRouter 只是国外的 API 中转/聚合平台，不是权威统计机构，其数据只是小样本 | 经验圈子信息 | "它就是一个 API 中转站，它是一个国外的 API 中转站，它的调用量小到什么程度呢"
- OpenRouter 过去一周调用量第一的模型约 6.13 万亿 token | 实测数据（引用榜单截图）| "过去一周他调用量是 6.13 万亿 token"
- 重度 API 用户单日最高可用约 20 亿 token，一周约 140~150 亿 token | 经验数据（UP 主自述用量）| "每一天我可以用到 20 亿 token……如果是一个星期的话，那可能就 140 亿甚至 150 亿"
- 只需要约 400 个重度用户就能把模型刷到 OpenRouter 周榜第一 | 量化估算（6.13 万亿 ÷ 150 亿 ≈ 409）| "你最少的话你只需要 400 个我，你就可以把你的这个模型冲到世界第一"
- Claude / GPT / Codex / Claude Code 等主流模型的用户量是几百万级，400 人规模与之相差 4 个数量级，故榜单第一 ≠ 真实调用量第一 | 常识对比 | "这些用户量都是几百万级的……我一个 400 人……就会变成一个世界第一的位置吗？我不相信"

## 知识点候选

- token ← 分词器（tokenizer）、文本最小计量单位
- API（大模型接口调用）← token、按量计费、客户端-服务端模型
- API 中转站 / 聚合平台（以 OpenRouter 为代表）← API、请求转发、API key 计费体系
- 调用量（token 吞吐量）与统计口径 ← token、统计时间窗口（周榜）
- 榜单排名与"世界第一"的口径问题 ← 调用量、统计口径
- 数量级估算（亿 = 10^8、万亿 = 10^12 的换算与除法反推）← token、科学计数法
- 刷榜（榜单操纵）及其成本 ← 调用量、API 按 token 计费
- 抽样偏差 / 样本代表性（平台数据 ≠ 全网数据）← 统计学基础（总体与样本）
- 主流模型与编码 Agent 生态（Claude、GPT、Codex、Claude Code）← LLM、Agent、编程工作流
- 两种度量口径的区别：用户量级（几百万级）vs 调用量级（token 数）← 调用量、用户量级
- 重度用户为何能单日烧 20 亿 token ← token、Agent 长上下文反复调用
