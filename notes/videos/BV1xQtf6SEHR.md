# BV1xQtf6SEHR 两张十年前 Pascal 老卡（P40+P106）+ 128G U盘跑 176B Qwen3.8-Flash：n-gram 查询表外挂与实测

> 字幕文件：`/data/data/com.termux/files/home/project/llm/videos/20260903-BV1xQtf6SEHR-2张10系显卡+U盘，怒推176B Qwen3.8Flash！30tk⧸s + 160K上下文.ai-zh.srt`
> 内容：UP 主用两张各 400 元的 Pascal 架构老卡（P40 + P106，合计 48G 显存），跑参数量 176B 的 Qwen3.8-Flash 的最低精度量化（IQ1_S，体积 72G）。核心技巧是把模型拆成"125B 主模型常驻显存 + 51B n-gram 查询表外挂"，因内存（16G）和硬盘（100G）都不够，最终把查询表放到 100 元的 128G U盘上运行；随后用自研开源测速工具 LLMSPEEDCHAT 实测解码速度、填充速度、160K 上下文和前端代码生成质量。

## 知识点候选

- **token / 分词** ← 语言模型基本输入输出单元
- **参数量（B=十亿参数）** ← 神经网络权重就是一堆浮点数
- **量化（quantization）** ← 浮点数表示（FP16/BF16）、权重存储大小估算（参数量 × 每参数比特数 / 8）
- **量化档位 IQ1_S / IQ3 / Q4** ← 量化、llama.cpp 的 k-quants/i-quants 命名体系、精度-体积-质量权衡
- **显存容量预算**：72G 模型 vs 48G 显存 ← 量化后的模型体积计算、显存=显卡上的高速存储
- **混合架构模型拆分：主模型 + n-gram 查询表** ← MoE 与"外挂模块"概念、模型文件里各部分的显存需求
- **n-gram 查询表 / PLE** ← n-gram 语言模型（统计式前驱）、大表查找加速、近似查表代替计算
- **offloading（权重卸载）** ← 显存层次结构（显存 > 内存 > 硬盘/U盘）、各层带宽差距
- **U盘/硬盘/内存带宽对推理的影响** ← offloading、顺序读取速度、为什么查询表（低频访问）适合放慢速介质
- **KV cache 与上下文长度** ← Attention 的 KV 缓存、上下文越长 KV 越大
- **KV cache 的 Q4 量化** ← KV cache、量化
- **Prefill 与 Decode 两阶段** ← Transformer 自回归生成、两阶段速度差异（314 tok/s vs ~29 tok/s）
- **tok/s（解码速度）作为核心指标** ← Decode 阶段、如何从日志（llama.cpp print_timings）读速度
- **MTP（多 token 预测）** ← Decode 每步只产 1 token 的瓶颈
- **投机解码（speculative decoding）** ← MTP、小模型草稿验证机制
- **reasoning budget（思考预算）** ← 推理模型的思考 token、思考量与生成时长/成本的关系
- **Pascal 架构 P40 / P106** ← GPU 型号谱系、数据中心卡 vs 矿卡、显存带宽与算力
- **多卡显存拼接跑大模型** ← 模型切分（层间切分）、多卡协同
- **功耗与二手性价比** ← TDP、4096 元级对比方案的机会成本（可外延）
- **MoE（Qwen3-30B-A3B）** ← 稠密模型 vs MoE、激活参数 vs 总参数
