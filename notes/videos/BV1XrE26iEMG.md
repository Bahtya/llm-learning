## 术语穷举

- **token / tok/s（每秒 token 数）**："2600tk/s"（标题）、"2600的prep数"——Prefill 速度的计量单位。

## 知识点候选

- token ← 分词器（tokenizer）、文本最小单位
- tok/s（每秒 token 数）← token
- Prefill 预填充阶段 ← token、注意力机制、KV 缓存
- Decode 解码阶段 ← token、自回归生成、KV 缓存
- Prefill / Decode 两阶段分离 ← Transformer 推理流程
- 首 token 延迟（TTFT）与"Prefill 快才是真的快"的体感逻辑 ← Prefill、Decode
- 参数量（27B）与权重大小估算 ← 参数量、数值位宽
- 浮点数表示 ← 二进制、计算机数值表示
- FP8 量化 ← 浮点数表示、量化
- INT8 / INT4 整数量化 ← 整数表示、量化
- GGUF 的 Q2/Q3/Q4/Q5 低比特档位 ← 量化、模型文件格式
- 量化位宽 vs 显存占用 vs 精度/速度的取舍 ← 量化、参数量
- 稠密模型（Dense）与 MoE 的区别 ← Transformer 架构
- MTP 多 token 预测 ← Decode、投机解码思想
- 为什么关掉 MTP 会拖慢 Decode 但不影响 Prefill ← MTP、Prefill/Decode 两阶段
- 上下文长度与长文本处理 ← 上下文、KV 缓存
- 输入形态（纯文本 vs 代码）对 Prefill 的影响 ← Prefill、分词器
- vLLM 推理框架 ← 推理引擎、KV 缓存、批处理
- AMD Quark 量化工具链 ← 量化、模型权重格式
- 2080 Ti / Turing（SM75）老架构 ← GPU 架构代际、CUDA
- 老卡跑新精度格式的软件适配（vLLM 2080Ti definitive 项目）← vLLM、GPU 架构、量化
- 显存容量与多卡分摊（30 多 GB 权重装进哪）← 显存、参数量、模型切分
- 模型仓库与可复现实验（权重清单公开）← Hugging Face/模型权重常识

## 金句与案例

- 【核心口号】"抵扣的快不是真的快，PREFU快才是真的快"——Decode 快不算快、Prefill 快才是真快，可作全书"两阶段速度观"的章节题眼（第 3-4 段）。
- 【对比基准】"千问3.6 27B稠密模型FP8权重下……实现了1600 1700的这样一个prefill速度"——上一期 FP8 的 Prefill 基线 1600–1700 tok/s（第 7-11 段）。
- 【实测数字】"他prefill是2500"——纯文本长输入（刘慈欣小说）的 Prefill 2500 tok/s（第 27-29 段）。
- 【实测数字】"你基本上秒回了2600的……2600的prep数"——长代码输入的 Prefill 2600 tok/s，且体感"秒回"（第 32-35 段）。
- 【对比案例】FP8 1600–1700 vs INT8 疯狗模式 2500–2600——更低位宽（INT8）反而填充更快，可作"速度瓶颈在带宽与 kernel 实现，精度不是唯一决定因素"的实测对比案例（第 9-11 段 vs 第 28/35 段）。
- 【精度宣言】"INT8权重啊，不是int4啊，也不是Q二Q三Q4Q5"——在速度与质量间选 INT8、拒绝更低比特的立场表达（第 16-19 段）。
- 【体量锚点】"全重30多G的权重"——27B INT8 全量权重约 30 多 GB，可作"参数量 × 位宽 = 权重体积"的速算案例（第 20 段）。
- 【实验控制】"当我们在这里我们关了MTP啊，所以呢他这一个解码速度不会很快"——诚实披露关闭 MTP 后 Decode 不快，示范"Prefill 与 Decode 指标要分开看"（第 36-37 段）。
- 【适用边界】"如果说你需要做一个更长文本的处理的话，那这个模式可能会比之前的模式更适合你那么一点点"——不吹万能，给出模式的适用场景（第 38-41 段）。
- 【可复现路径】"就这个Quark，AMD Quark量化的这个INT8权重……我们仓库地址VLLM2080Ti definitive"——权重来自 AMD Quark 量化、测试清单与仓库公开，可作"如何复现别人跑分"的教学案例（第 42-46 段）。
