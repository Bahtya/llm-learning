## 论断清单

- 只要两张卡显存相同（如 16G+16G），其 prefill 速度一定比一张 32G 的卡快 | 实测数据（多组对比）| "只要是两张卡同样的显存，比如像 16G 加 16G，它的 prefill 的速度一定是比一张 32G 的要快"（第 13-15 段）
- 没有 NVLink / P2P / 大带宽，多卡照样能加速——这是对网友普遍误解的辟谣 | 经验圈子信息 + 实测 | "如果两张卡之间没有 nv link、没有 p to p、没有大带宽，那么是不是多卡它就不能加速呢……我们要进行一个辟谣"（第 3-11 段）
- 模型约 25GB（千问 Q4 量化）一张 16G 放不下，拆到两张 16G 里，速度不会比一张 32G 慢 | 实测数据 | "他只有大概 25 个 G……我一张 16G 也放不了，那我用两张放进去，那么它的速度会不会比一张 32G 的要更慢？答案是不会"（第 27-33 段）
- 卡间拓扑良好（NVLink、xGMI 等高速互联）时，张量并行可以对 decode 加速 | 原理推导 | "有了这样的 NVLINK、xGMI 等高速卡间互联情况下，那么张量并行他是可以进行 decode 的加速"（第 17-20 段）
- 双卡流水线并行下 prefill 提升幅度：170HX 约 +72%，MI250 约 +60%，2080 约 +50% | 实测数据 | "双卡情况下……它的 PPU（prefill）速度大概增加了 72%"（第 58 段）；"双卡他的 prefill 速度是比单卡要快 60%"（第 71 段）；"2080 它也是这样，他能快 50%"（第 74 段）
- 双卡流水线并行下 decode 速度不劣化（三种卡、不同 PCIe 代际均如此） | 实测数据 | "它的解码速度没有劣化"（第 59-60 段）；"不管是 PCI1.0 x4 还是 PCIE2.0 x16……第一点他 decode 解码速度它不会劣化，第二点他的 PFU（prefill）速度大大增快"（第 81-88 段）
- PCIe 5.0、NVLink 与否，对流水线并行的性能没有任何影响 | 原理推导（通信量估算）| "所以别说什么 PCIE5.0，别说什么 nv link、PCI1.0 x4，对于这个性能都没有任何影响"（第 121-123 段）
- 流水线并行时卡间通信在 prefill 阶段只发生一次（每 ubatch 一次），传的是分界层（第 20 层）的 hidden state，量级仅几 MB 到几十 MB | 原理推导 + 量化估算 | "其实在 prefill 阶段每一次通信它只需要通信一次……可能就几兆到几十兆，因为它传递的是第 20 层的 hidden state"（第 107-119 段）
- 解码阶段卡间数据交换量更小，只有几 KB，基本可以无视 | 量化估算 | "解码阶段它的这个数据交换量更是小的不行，可能就几 KB 啊，所以呢基本上是可以无视的"（第 125-127 段）
- 流水线并行（在 llama.cpp 中叫 layer split）是一定能够加速 prefill 的 | 原理推导 + 实测 | "对于这个流水线的并行，我们也可以叫在 llama.cpp 里面叫 layer split，他是一定能够去加速的"（第 128-130 段）
- 双卡 prefill 加速的原理：第一张卡算完自己那 20 层、把 hidden state 传过去后，立刻开始算下一个 batch，两张卡的计算时间重叠 | 原理推导 | "这张卡又开始去算下一个 batch……这边已经在算，这边下一个 batch 也开始在算……这就是双卡流水线加速的这个原理"（第 147-152 段）
- 单卡则必须先把第一个 prompt 全部处理完，再处理下一个，没有流水重叠 | 原理推导 | "他要把第一个 prompt 全部处理完，然后呢再去处理下一个的这个 prompt"（第 158-159 段）
- 解码是 per token 的自回归输出：一个 token 必须等第 1-20 层和 21-40 层全部算完，才能开始算下一个 token，因此流水线并行不能提升 decode 速度 | 原理推导 | "解码阶段它的一个问题就在于它是我们叫做 per token 的这个输出……他首先要第一层到第 20 层全部算完之后，然后把第 21 层到 40 层全部算完……他才开始去算下一个"（第 169-178 段）
- 流水线并行不能加速 decode，但也不会减速 | 实测数据 | "这就是为什么我说的这个流水线并行它不能够对这个解码速度进行提速的一个原因，但是他也不会减速，因为我们实测里面已经出现了"（第 179-182 段）
- 张量并行是每层左右各算一半、每一层都要做 all-reduce 全局规约交换，等效于显存带宽翻倍，所以能对解码速度翻倍 | 原理推导 | "左边算一半，然后呢右边算一半……每一层他都要去进行交换，也就是说我们这全局规约 all-reduce……他就相当于他的显存的带宽翻倍了，所以这就是张量并行他为什么能够对解码速度进行翻倍"（第 186-196 段）
- 张量并行不一定能达到理想的翻倍，但只要拓扑关系还好，decode 速度肯定比单卡快 | 经验圈子信息 + 实测 | "当然他不一定能够达到理想翻倍……但是的话他解码速度通常如果在拓扑关系还好的情况下，他是肯定会比单卡要快的"（第 198-201 段）
- 170HX 这类矿卡需要补电路（飞线改装），改装后只有 PCIe 1.0 x4 | 经验圈子信息 | "就这些卡我们要去补电路啊，所以他是 PCI1.0 x4"（第 82-83 段）
- 上述结论只针对语言模型，不适用于文生视频、文生图模型 | 经验圈子信息（限定范围）| "我们不说的这扩大模型不说这个文生视频、文生图，这个视频我们就说语言模型它是这样情况"（第 163-165 段）
- 测试时使用了 4K prompt、2K ubatch 的配置（每次前向处理 2K token 的块） | 实测配置 | "我们整一次单次输入是 4K 的这个 prompt，然后我们在 u batch 里面比如像我们是 2K 的这个 UBATCH"（第 134-136 段）
- 上一个 MI50 视频已讲过 prefill 加速结论，本视频补充三组相同卡的数据 | 经验圈子信息（自引）| "其实我们上一个视频关于 MI50 里面我们就已经讲过了，但我觉得这还是可以额多几个数据"（第 36-38 段）

## 金句与案例

- "只要是两张卡同样的显存，比如像 16G 加 16G，它的 prefill 的速度一定是比一张 32G 的要快"——全片核心辟谣结论（第 13-15 段）
- 【实测数据】170HX 单卡 → 双卡流水线并行：prefill 速度约增加 72%，解码速度没有劣化（第 43-60 段）
- 【实测数据】MI250 双卡 layer split：prefill 比单卡快 60%（第 62-71 段）
- 【实测数据】2080：双卡能快 50%，且其 PCIe 带宽/拓扑关系很不理想（2080Ti 还接了 NVLink）（第 72-80 段）
- 【翻车/成本细节】170HX 等矿卡要补电路（飞线），所以只有 PCIe 1.0 x4——极差带宽下结论依然成立（第 81-84 段）
- 【量化估算】prefill 阶段卡间每次只通信一次，传第 20 层 hidden state，仅几 MB 到几十 MB（第 107-119 段）
- 【量化估算】decode 阶段卡间数据交换量只有几 KB，"基本上是可以无视的"（第 125-127 段）
- 【配置锚点】4K prompt + 2K ubatch 的实测配置（第 134-136 段）
- 【模型体积锚点】千问 3 系列 Q4 量化模型约 25GB（也提到 40GB 量级），单张 16G 放不下、双 16G 放下后不比 32G 单卡慢（第 26-33 段）
- 【原理金句】张量并行"相当于他的显存的带宽翻倍了"，所以解码速度能翻倍（不一定达到理想翻倍）（第 194-199 段）
- 【原理金句】双卡 prefill 加速的本质：第一张卡传完 hidden state 就去算下一个 batch，两卡计算重叠；单卡只能"先把第一个 prompt 全部处理完，然后再去处理下一个"（第 147-159 段）
- 【范围限定】结论只说语言模型，"不说这个文生视频、文生图"（第 163-165 段）
