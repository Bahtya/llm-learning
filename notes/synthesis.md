# 方法论综合分析（写作阶段参考）

## SPOTLITE 的认知闭环（从 22 个视频归纳）

他的每个判断都走同一条链：**现象/质疑 → 查一手资料（模型卡/规格表）→ 列公式算账 → 上机实测 → 公开复现（GitHub 验证矩阵）**。

七个反复出现的方法论模式：

1. **先算账再动手**：大额决策前先列公式估算（KV 显存账、电费账、24h token 产出账、显存预算三本账）。公式本身也要审——"这公式对的吗？"
2. **不信二手结论，信一手字段**：KV 那期的翻案全靠模型卡 Layer type 字段（64 层只有 1/4 全注意力）。他会打开 config.json 给你看。
3. **控制变量对照实验**：PCIe 1.0x4 实验同模型/同量化/同 prompt；MTP 对比多场景×多 N 值画曲线；承认速度波动，区分"最高速度"和"稳定复现速度"。
4. **口径批判**：任何"世界第一/最强"先问统计口径——周榜调用量 vs 用户量级、抽样偏差、刷榜成本，用除法反推数量级是否合理。
5. **成本工程**：一切以价格锚点表达——每 TFLOPS 多少钱、每 64G 内存多少钱、TCO（购置+电费+精力+矿卡风险）、机会成本（这两万元买 A 还是 B）。
6. **以终为始**：先定工作负载（个人单并发？Agent？AIGC？）再反推硬件；"能不能跑"先于"跑得快不快"。
7. **开源复现 + 社区校验**：所有结论落到 GitHub 仓库的 🟢🟡🔴⚪ 验证矩阵，Discord 社区互相复现；选模型看社区支持度。

## 对写书的三条指令

1. 每个概念**从零讲起**，读者是"看过视频但卡壳"的开发者：先给直觉/类比，再给公式，最后给视频里的真实数字做锚点（标注 BVID）。
2. 每章尽量带「**怎么验证**」小节：告诉读者怎么自己复现这个结论（查哪个字段、跑哪个命令、算哪笔账）——这是把他的方法论渗透进内容的载体。
3. 机器字幕错别字已在笔记中校正（LP16→FP16、丑密→稠密、解码→Gemma 等），引用时用校正后的写法。
