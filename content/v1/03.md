## 一层不叫模型，几十层叠起来才叫

上一章的[生成 = 预测下一个 token](#/v1/02)只讲了"决策那一刻"：logits 经 softmax 变成概率分布，采样出一个字。本章补上决策之前的流水线：这个字是几十道同名工序串行加工出来的。Transformer 就是把同一种层结构反复堆叠出来的机器。类比工厂质检线：原料进来，每过一道工位被精修一次；浅层认词形，中间层认搭配，深层才认语义，越深越抽象。视频里动辄说的 40 层、60 层、64 层，就是工位数。

## 层间流动的东西：hidden state 与 hidden size

每个 [token](#/v1/01) 先被查成初始向量，这张初始向量表叫嵌入层（embedding），之后每过一层就被改写一次。这个"加工中的中间结果"叫隐藏状态（hidden state）；它的宽度，也就是用多少个数字描述一个 token，叫 hidden size（隐藏维度）。把整条序列排成矩阵：一行一个 token，每层做的事都是"读进来、算一遍、写回去"，形状不变，内容越来越"有想法"；最后一层的 hidden state 才拿去算 logits。注意力头也是从 hidden size 上切出来的：切成若干个头、每头 head_dim 维并行去"看"别的 token（详见[注意力](#/v1/04)）。

## 每层 = 注意力 + FFN

每层固定两步：

- **注意力（attention）**：让序列里的 token 互相交换信息，决定"我在看谁"；
- **前馈网络（FFN，feed-forward network）**：对每个 token 独立做一次带弯折的变换（弯折=不是一条直线算到底，中途会拐弯，行话叫非线性，而非简单加权求和），参数大头在这里。

所以，**权重（weights）**是按层分布的。所谓 27B，不是一个整体大矩阵，而是 64 份"每层一份"的权重叠出来的账本。这解释了两件事：权重显存 ≈ 每层参数 × 层数 × 每参数字节数（[显存三本账](#/v4/02)）；多卡可以"按层对半切"，40 层你放 20 我放 20（[TP vs PP](#/v4/06)）。

## 层数是显存和串行度的公共乘数

- 显存：[KV 缓存](#/v1/05)公式的第一个乘数就是层数，层数翻倍、KV 账翻倍。
- 串行度：decode 是自回归的，第 n+1 层必须等第 n 层算完；一个 token 要把全部层顺序跑完，才轮到下一个 token。prefill（吞输入的阶段，见 [Prefill 与 Decode](#/v1/07)）能让不同 batch（一次并排送进模型的一批 token，见 [并发与批处理](#/v3/04)）在层间流水重叠，但单条序列的层依赖消不掉（[Prefill 与 Decode](#/v1/07)）。

> **案例（视频出处：BV1YxjU6qEuw）**
> UP 主用 40 层模型画图（视频随手设的举例层数，非真实模型）：8K 的 prompt 拆成 4 个 2K batch，单卡只能"跑完全部 40 层，再跑下一个 batch"；换成两张卡各放 20 层做流水线，第一个 batch 算到一半就让第二张卡接手，第一张卡立刻开跑下一个 batch，等效同时在算 4K prompt。35B 级模型的 prefill 速度从 600 多 tok/s 涨到 1000 多，约 +60%。但 decode 一点没快：自回归必须"前 20 层跑完再跑后 20 层"才吐得出下一个字。

> **案例（视频出处：BV1UMEv68E3C）**
> 模型卡 Hidden layer 字段：千问 27B 稠密模型是 64 层，Gemma 是 60 层（书中"千问 27B"为视频口播转写，层数与 32B 级吻合，以模型卡为准）。在 [KV 缓存](#/v1/05)的显存公式里，层数是第一个乘数，这个数取错一档，整笔账能差好几倍，翻案见[注意力的三个变体](#/v1/06)。

> **案例（视频出处：BV1qU846JEpW）**
> 一次请求的链路里，真正压在 GPU 上的就是"把几十层顺序过一遍"：prefill 把输入过一遍全部层，decode 每吐一个字再过一遍，末尾才 softmax 出"北京 70%、上海 20%、天津 3%"这样的分布。层越多、每一遍越贵，所以 CPU 频率从 1.5G 提到 5G，只是把 CPU 侧几十毫秒压到十几毫秒，整体几乎无感；预算该花在层数所在的显卡上。

## 怎么验证

- 打开 Hugging Face 模型页，读模型卡（model card）或 `config.json` 的两个字段：`num_hidden_layers`（层数）、`hidden_size`（隐藏维度）。千问 27B 应显示 64 层，Gemma 应显示 60 层。
- 用 llama.cpp 跑任意 GGUF（模型文件格式，见 [INT8/INT4 与 GGUF 档位](#/v2/03)），看启动日志：`n_layer` 与 `n_embd` 就是层数和 hidden size。
- 把 `n_layer` 代进 [KV 缓存](#/v1/05)公式当第一个乘数，亲手算一遍"层数翻倍 → KV 翻倍"；再对照[显存三本账](#/v4/02)检查权重账是否 ≈ 参数量 × 字节数。
