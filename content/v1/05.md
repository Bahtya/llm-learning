## KV 缓存：用显存换算力

生成是自回归（autoregressive）的：模型一次只吐一个 token（见 [生成 = 预测下一个 token](#/v1/02)）；注意力（attention）又要求每个新 token 都"回头看"全部历史（见 [注意力：每个 token 都在看谁](#/v1/04)），看的是历史各 token 的 K 和 V。这批 K、V 算一次就不会再变，于是每出一字，只需为新 token 算一组 K/V 接到缓存末尾，旧账原封不动。这笔不重算的旧账就是 **KV 缓存（KV cache）**。

拿读书打比方：每读到一个新词都要回头对照前文，与其每次从头重读全书，不如边读边做摘要卡，之后只翻卡片。K 像"关键词索引"，V 像"内容摘要"。没有缓存时，每生成一个 token 都要把全部历史的 K/V 重算一遍，计算量随进度越滚越大；有了缓存，每步只算新 token 那一组。省下的是成倍的重复计算，代价是一块常驻显存，所以说它是"用显存换算力"。

### 公式：KV 到底吃多少显存

```formula
KV 显存 = 层数 × KV头数 × head_dim × 2 × 序列长度 × 每元素字节数
```

- **层数**：Transformer 按层堆叠（[v1/03](#/v1/03)），每层各存一份 K/V
- **KV头数 × head_dim**：每个注意力头（attention head）一组 K、V 向量，head_dim 是向量长度
- **×2**：K 和 V 各存一份
- **序列长度**：上下文（context）里的 token 数（[v1/01](#/v1/01)）
- **字节数**：FP16 每个数 2 字节（见 [浮点数从零讲起](#/v2/01)）

> **案例（视频出处：BV1UMEv68E3C）**
> UP 主代入"满血 256K、FP16"：千问（Qwen）27B（书中型号为视频口播转写，口径见 [模型生态与幻觉](#/v1/10)）稠密（dense）模型的模型卡标注 64 层，算出 **64G**；60 层的 Gemma 更算出 **120G**。直到他点开模型卡的 Layer type 字段，才发现 64 层里只有 1/4 是全注意力。公式错在哪、64G 怎么变成 16G，是[下一章](#/v1/06)的翻案主角。

### GQA：为什么公式写"KV 头"

"头"分两种：Q 头负责"我在找什么"，K/V 头负责"被找到时亮出的名片"。很多模型采用 GQA（Grouped-Query Attention，分组查询注意力）：多个 Q 头共享一组 K/V 头，所以 config 里 `num_attention_heads` 大、`num_key_value_heads` 小，KV 缓存只跟后者成正比。既然缓存是长上下文最大的显存压力，砍 KV 头数（几乎不伤模型智力）就是架构层面省显存的第一刀：不量化任何数字，缓存先按分组比例缩小。

### 上下文越长，KV 越大

公式里唯一的"活变量"是序列长度：权重装完就不动，KV 却随对话实时增长，上下文翻倍，KV 翻倍，严格线性。所以模型卡上的长上下文不是免费标签，背后是一笔显存账（见 [上下文窗口与思考预算](#/v1/08)）；多轮对话的历史不清空，KV 就不会下降；显存不够时只能砍上下文，或砍并发，因为每个并发请求都要一份自己的 KV（见 [并发与批处理](#/v3/04)）。注意力变体能改变这条增长曲线，见[下一章](#/v1/06)。

### 三本账里的 KV 项

显存三本账 = 权重 + KV 缓存 + 计算缓冲区（见 [显存三本账](#/v4/02)）。权重是死账、KV 是活账：三本里只有 KV 随使用增长，上下文再长一点、并发再多一路，都是往这本账上加钱；显存吃紧时，最先砍的就是它。

> **案例（视频出处：BV1UMEv68E3C）**
> 修正后的总账：两张 22G 的 2080Ti（22G 为魔改加大版，原版 11G，见 [显卡市场生存指南](#/v4/10)）共 44G = 20G 权重（AWQ INT4，一种 4 bit 量化格式，见 [INT8/INT4 与 GGUF 档位](#/v2/03)）+ 16G KV（256K、FP16）+ 剩余留给计算缓冲区，UP 主原话"绰绰有余"。

> **案例（视频出处：BV1i6Y86AEv3）**
> 反面案例：24G 单卡硬跑 256K 满血上下文，KV 只能压到 Q4 级，UP 主原话"幻觉它会爆炸到什么程度"。KV 也能量化换显存，精度代价见 [量化的代价](#/v2/06)。

## 怎么验证

- **查字段**：Hugging Face 模型页 → Files → `config.json`，看 `num_hidden_layers`（层数）、`num_key_value_heads`（KV 头数）、`head_dim`（缺了就按 `hidden_size ÷ num_attention_heads` 算）、`torch_dtype`（半精度按每数 2 字节）
- **跑公式**：

```python
layers, kvh, hd, seq, b = 64, 8, 128, 262144, 2   # 代入查到的真实值
print(layers * kvh * hd * 2 * seq * b / 1024**3)   # 64.0，对上视频的 64G
```

中间量更好记：每 token 的 KV = 64×8×128×2×2 = 256 KiB（约 26 万字节），上下文乘几倍、KV 就乘几倍。

- **确认 GQA**：`num_key_value_heads` 小于 `num_attention_heads`，比值就是省下的缓存倍数
- **亲眼看**：把输入从 1K 加长到 32K，另开终端跑 `nvidia-smi`，显存应近似直线上升，斜率≈每 token 的 KV 字节数
