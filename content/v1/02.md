## 先看直觉：模型在玩接龙

模型不会打腹稿。把它想成玩成语接龙的人：从不整段想好再开口，每次只接一个词；接完，这个词被加进题目，他再看下一个该接什么。大语言模型的生成就是这个循环——它唯一会做的事，是给定前面全部内容，算出"下一个 [token](#/v1/01) 是什么"。

这叫自回归（autoregressive）：自己的输出回头当输入。吐一个 token、拼回句尾、再吐下一个，直到吐出结束符。你在屏幕上看到的打字机式"逐 token 输出"，就是这样一圈一圈转出来的。

> **案例（视频出处：BV1qGh56JEj2）**
> "一次只吐一个"是有代价的：每吐一个 token，都要把整只模型完整跑一遍前向（forward：把输入从头到尾过一遍所有层）——视频里的千问主模型有 64 层。这就是解码（decode）天生串行、加速困难的根源，也是 [Prefill 与 Decode](#/v1/07) 两阶段速度差异的源头。后来的投机解码（speculative decoding）本质就是让小模型一次猜 8~10 个 token、大模型一次校验，猜对的比例（接受率）决定加速比，详见[投机解码](#/v3/06)。

### 一圈循环：logits → softmax → 抽签

每一圈分三步：

- **打分**：整只模型对当前全部 token 做一次前向，最后一层给词表（vocabulary）里的每个 token 出一个原始分数，叫 logits。词表十几万条，logits 就是同样长的一排数；它们是任意实数，加起来不等于 1，不能直接当概率用。
- **归一化**：softmax 把这排数压成概率分布（probability distribution）——每项落在 0 到 1 之间，总和恰好为 1。带温度的公式是：

  `P(i) = exp(z_i / T) / Σ_j exp(z_j / T)`

  其中 `z` 是 logits，`T` 是 temperature。softmax 的特点是"赢家多吃"：分数差一点，概率差一大截。
- **抽签**：按这把概率进行采样（sampling），抽中谁，谁的 token id 就被拼回句尾，成为下一圈输入的一部分。

视频里描述的一次请求链路正是收尾于此：decode 完做 softmax 得到分数，采样出 token，再经反 tokenize（detokenize）变回文本（分词与反分词见 [token、词表与 BPE](#/v1/01)）。顺带一句，"每吐一个 token 都要读全部历史"带来的重复计算，正是 [KV 缓存](#/v1/05)要解决的问题。

> **案例（视频出处：BV1qU846JEpW）**
> 视频用的例子：decode 之后过 softmax，得到"北京 70%、上海 20%、天津 3%"这样的分布；temperature 等于 0 时就是贪心采样（greedy sampling），直接输出"北京"。真实的 logits 是整张词表十几万个数一起竞争，头部吃掉大头、其余分薄零头，形状和这个三位候选的例子一致。

### temperature：同一排 logits 的松紧旋钮

temperature 不改变谁是第一，只改变差距被放大的程度：

- `T` 变小：指数变陡，第一名吃掉更多概率，分布变尖；
- `T → 0`：概率全部塌缩到第一名——这就是贪心采样，永远选最高分，输出完全确定、可复现；
- `T` 变大：分布摊平，冷门 token 也有机会被抽中，输出越发散。

拿同一排 logits（3.0、2.3、1.2）亲手过一遍公式：

| T | 第一名 | 第二名 | 第三名 |
|---|--------|--------|--------|
| 0.5 | 78.5% | 19.4% | 2.1% |
| 1.0 | 60.2% | 29.9% | 9.9% |
| 2.0 | 47.4% | 33.4% | 19.3% |

榜首始终是同一个，但第三名的份额从 2% 涨到 19%。所以"调温度"调的不是答案，而是敢不敢让冷门上位。

### 为什么"一次一个"值得单独一章

两个后果。其一，上一步抽中的 token 会成为下一步的既成事实——模型一旦说出口"北京"，"上海"就永远出局，所以早期抽歪会把整段带偏，这是输出发散与幻觉的机制性来源之一（幻觉的定义见[模型生态与幻觉](#/v1/10)）。其二，串行循环把速度钉死了：一秒能吐多少 token，取决于一秒能跑多少圈完整前向，这笔账在[带宽决定 Decode、算力决定 Prefill](#/v4/03) 里展开。

## 怎么验证

验证需要本地模型环境（llama.cpp 或 vLLM，见 [推理框架两流派](#/v3/02)）与一张显卡；没有环境可跳过，不影响后续阅读。

1. **手算一遍**：任取三个 logits（比如 3.0、2.3、1.2），除以 T、取 exp、再归一化，检查三件事：每项都小于 1、总和等于 1、T 变小时第一名占比上升。

   ```python
   import math
   def softmax(z, T=1.0):
       e = [math.exp(x / T) for x in z]
       s = sum(e)
       return [round(x / s, 3) for x in e]

   print(softmax([3.0, 2.3, 1.2], T=1.0))   # [0.602, 0.299, 0.099]
   print(softmax([3.0, 2.3, 1.2], T=0.5))   # [0.785, 0.194, 0.021]
   ```

2. **跑命令**：用 llama.cpp（本地推理工具，见 [推理框架两流派](#/v3/02)）对同一 prompt 各跑两次——`--temp 0` 两次逐字相同（贪心采样没有随机性），`--temp 1.5` 则每次都可能不同。

   ```bash
   llama-cli -m model.gguf -p "中国的首都是" -n 8 --temp 0    # 两次输出完全一致
   llama-cli -m model.gguf -p "中国的首都是" -n 8 --temp 1.5  # 每次都可能不一样
   ```

3. **看真实分布**：vLLM（服务级推理框架）、SGLang（同为服务级推理框架，见 [推理框架两流派](#/v3/02)）/llama.cpp server 都兼容 OpenAI 接口参数，在请求里加 `"logprobs": true, "top_logprobs": 5`，返回中能看到每个位置头部候选的对数概率（logprob）。把两个候选的 logprob 相减再取 exp，就是它们的概率之比：`p1/p2 = exp(lp1 − lp2)`；换不同的 T 各请求一次，比值的变化就是温度公式的实况。
