## 回头看：注意力的直觉

[v1/02](#/v1/02) 讲过，自回归（autoregressive）生成就是不断预测下一个 token。但预测的依据是什么？答案是注意力（attention）：生成新 token 之前，模型让当前位置"看"一遍它之前的所有 token，给每个打一个相关度分数，再按分数把各 token 的信息加权汇总，汇总结果参与这次预测。

类比：你接手一份五千行的代码文件要续写下一行。动手前会扫一遍全文，刚写的几行看得最细，文件开头的 import 和函数定义行也要回头看一眼。注意力就是把这场"回头看"机制化：分数决定每个历史 token 的话语权，话语权决定下一个 token 的概率分布。

而且这场回头看发生在每一层：[v1/03](#/v1/03) 说过每层都是注意力加 FFN，所以 64 层的模型等于把同一份历史从 64 个不同角度各看一遍。层数越多、历史越长，"看"这个动作就越贵。本章后面所有账，都从这里长出来。

### QKV：一次检索的三个角色

注意力把每个 token 变换出三个向量（由 [v1/03](#/v1/03) 说的那一层的权重算出来）：

- **Query（查询）**：当前位置在问"我在找什么"；
- **Key（键）**：每个 token 的标签，回答"我能提供什么"；
- **Value（值）**：真正被搬走使用的信息。

流程只有三步：拿 Q 和所有 K 算相似度得分；得分过一遍 softmax 归一化成加和为 1 的权重（softmax 见 [生成 = 预测下一个 token](#/v1/02)）；再用权重对 V 加权求和。得分越高，那个 token 的 V 进入下一层计算的比例越大。谁的 Key 和我的 Query 最匹配，我就多看谁。注意 Q、K、V 都是向量，"检索"只是类比：匹配度是算出来的连续分数，不是关键词命中。

### KV 缓存为什么存在

关键观察：历史 token 的 K 和 V 只由它自己决定，生成新 token 时完全不变。朴素做法是每生成一个 token，就把全部历史重新算一遍 K 和 V，纯属重复劳动。把算好的 K、V 存起来复用，就是 KV 缓存（KV cache）：用显存换算力。它为什么动辄比权重还大、公式怎么列，是下一章 [KV 缓存：用显存换算力](#/v1/05) 的主角，这里只记住因果：先有注意力要反复读历史，才有 KV 缓存。

### 注意力与序列长度的关系

序列长度（sequence length）L 越长，注意力在两个维度同时变贵：

- 计算：新 token 要和全部历史两两打分，单层分数数量约为 L²/2（每个 token 只对它之前的历史打分），随长度平方增长；
- 显存：全注意力层（full attention）的 K、V 都按序列长度逐 token 存放，KV 缓存随 L 线性增长。

> **案例（视频出处：BV1UMEv68E3C）**
> 把 256K 的上下文代进 [KV 缓存](#/v1/05)公式，观众直觉"要占几十个 G 甚至上百 G"正来自"序列长度 × 注意力层数"这根杠杆。不过按层粗算会把账放大好几倍，翻案见 [注意力的三个变体](#/v1/06)。

> **案例（视频出处：BV1i6Y86AEv3）**
> 同一期还给了反面账：24G 显存硬跑 256K 满血上下文，KV 只能压到 Q4 级（4 bit 量化档，量化即用更少的比特存数，见 [INT8/INT4 与 GGUF 档位](#/v2/03)），"幻觉会爆炸到什么程度"；KV 精度的代价见 [量化的代价](#/v2/06)。

所以上下文窗口不是免费参数：它同时推高计算量与 KV 显存。吞 prompt 和吐 token 两个阶段谁更吃这个账，见 [Prefill 与 Decode](#/v1/07)。

## 怎么验证

- 查字段：Hugging Face 模型页 → Files → `config.json`，看 `num_hidden_layers`（层数）、`hidden_size`、`num_attention_heads` 与 `num_key_value_heads`（KV 头，下一章的公式要用）；不少模型卡正文直接给出 Layer type 分布表。
- 数 token：用 tokenizer 把一段话转成 id 数一数（见 [token、词表与 BPE](#/v1/01)），得到的就是注意力里的 L。
- 算一笔分数账：千问 27B（64 层）在 256K（L≈26 万）下，单层注意力分数约 260000²/2 ≈ 338 亿个，64 层累计约 2.2 万亿个。
- 看 KV 线性：vLLM（服务级推理框架，见 [推理框架两流派](#/v3/02)）起服务时把 `--max-model-len`（最大上下文长度参数）从小到大调几档，用 `nvidia-smi`（英伟达显卡状态查看命令）记录显存占用，全注意力模型的 KV 部分会近似线性上涨。把这组数留好，正好当下一章公式的实测数据。
