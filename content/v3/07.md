## 内核与算子：快从哪里来

引擎选好、量化也定了，为什么同一张卡换个引擎或格式，速度差好几倍？因为真正干活的不是 vLLM 这层"软件"，而是 GPU 上一段段叫**内核（kernel）**的小程序。本章讲三件事：kernel 是什么、Tensor Core 三代差在哪、"INT8 算力翻倍"怎么兑现成速度。

### kernel：一道工序，不是一个软件

把推理引擎想成餐厅：前厅接单、排队、上菜（见 [vLLM 与 PagedAttention](#/v3/03)），后厨才是炒菜的地方。模型一层 = 注意力 + FFN（见 [Transformer：按层堆叠的机器](#/v1/03)），展开是一串矩阵乘（GEMM，General Matrix Multiply）与逐元素运算（每个数各自算一遍）——**每种运算对应一个 kernel**：被上万线程同时执行的一段 GPU 函数。Prefill 的大矩阵乘、Decode 的小矩阵乘、softmax、反量化（dequantize），各是不同的 kernel。启动 kernel 有固定开销，一秒几千次发射相当可观——这正是 [CUDA Graph](#/v3/05) 要消掉的发射开销。

### Tensor Core：专吃矩阵的单元

普通核心一次算一个数的乘加；**张量核心（Tensor Core）**一次吃一小块矩阵。它随 Volta（V100）问世，三代演进差别主要在"会算什么格式、怎么喂数据"：

| 代际 | 代表 | 新增能力 | 明显短板 |
| --- | --- | --- | --- |
| 第一代 | Volta / V100 | FP16 矩阵乘 | INT8 只有融合算子，凑不出矩阵乘 |
| 第二代 | Turing / 20 系 | INT8 矩阵乘，算力 = FP16 × 2 | 无 FP8 |
| 第三代 | Ampere / 30 系 | cp.async 异步拷贝、异步流水线 | FP8 要等 Ada，代际总表见 [架构代际](#/v4/04) |

> **案例（视频出处：BV1E5426eE5X）**
> V100 挂第一代 Tensor Core，FP16 算力 130T（口播口径；官方约 112~125T，视版本），同一个 7B 模型短测 Prefill 约 3000 tok/s，MI50 只有约 1000。但 V100 带宽 900GB/s 明明低于 MI50 的 1TB/s，Decode 反而反超——"你读的再快你算不过来他还是慢"。MI50 输在算力利用与指令调度，不是带宽不够。算力决定 Prefill、带宽决定 Decode（见 [Prefill 与 Decode](#/v1/07)、[带宽决定 Decode、算力决定 Prefill](#/v4/03)），可喂不饱时带宽再大也白搭。

### DP4A：没有 Tensor Core 时的凑合方案

Tensor Core 出现之前，Pascal 用一条叫 **DP4A** 的指令给 INT8 续命：4 个 8 位整数相乘再相加，一条指令做完。它属于"融合算子"思路——几步并成一条指令，与整块矩阵的 Tensor Core 不是一个量级。同一代里有没有它，差距直接写进实测：

> **案例（视频出处：BV1E5426eE5X）**
> P100 是帕斯卡唯一 SM60 专业卡，700GB/s 带宽、双倍半精度加速，但整代缺 INT8/DP4A 加速；150 元的矿卡 P102 有 DP4A，Prefill 能上千，P100 只有 700 多。专业卡的体面，输给了一条指令。

### 快的另一半：把数据喂到位

算力单元再快，数据没到位就是空转。第三代 Tensor Core 的 **cp.async 异步拷贝**允许"算这一块的同时，把下一块搬进片上内存（芯片内部的小块高速存储）"，流水线不空转——这正是它指令能力远强于前两代的原因。

> **案例（视频出处：BV1hLtG6ZE5M）**
> 魔改 3070 系 FP16 只有 70 多 T、INT8 150T，纸面不如 2080S 魔改版，却凭第三代 Tensor Core 实测推理更好；没有张量核心的中科海光 Z100L（国产卡，见下一章），Decode 靠两倍显存带宽"力大砖飞"（圈内说法：不玩技巧、纯堆硬件硬算），也只拿到魔改卡约九成解码，Prefill 更慢；V100 32G 显存管够却"存得下、算不过来"，缺的正是 INT8 矩阵加速——指令能力而非纸面 TOPS 决定速度。

### 算子库：Marlin 与 Flash 家族

量化模型走反量化路线（见 [权重与激活：W8A16 命名的世界](#/v2/04)）：4/8 位权重现场还原成 FP16 再算。在 vLLM 里负责算 A×W 的是点名指定的 **Marlin**，它把数据排布、反量化、矩阵乘捏成一道工序喂饱 Tensor Core（省带宽的账见 [量化粒度与异常值：Marlin 为什么快](#/v2/05)）。注意力同理有一族专用 kernel：**FlashAttention** 把 Q×K、softmax、V 加权融成一道工序，不把中间大矩阵写回显存；这一家族里 vLLM/SGLang 等引擎常用的后端库是 **FlashInfer**——UP 主口播似作"FlashQLA"，实指的就是它这一系。

### INT8 TOPS = FP16 × 2：账怎么兑现

Tensor Core 的吞吐随位宽翻倍：格子从 16 位减到 8 位，同样一轮搬进来的数多一倍，所以 **INT8 TOPS = FP16 × 2** 是架构设定，不是营销话术。但兑现有个硬前提：激活值也得是 8 位，即 W8A8 才吃得到；W8A16 反量化路线终究在 FP16 上运算，吃不到这份翻倍。

> **案例（视频出处：BV14yT46kE5T）**
> 2080Ti 不支持 FP8 加速，但支持 INT8 加速，且 INT8 算力比 FP16 再翻一倍；全生态翻下来只有一个方案能吃上：AMD Quark 量化的 W8A8——8 位整数权重不反量化、直接在 8 位激活上运算，Prefill 大大增快，但当时有 bug，Decode 非常慢。

一句话收束：**快 = 合适的 kernel × 喂得饱的数据 × 用得上的格式**，缺一项，TOPS 就只是纸面数字。

## 怎么验证

- **查自己卡的代际**：`python -c "import torch; print(torch.cuda.get_device_capability(0))"`，输出 (7,0)=Volta、(7,5)=Turing、(8,6)=Ampere，对照上表即知有哪些格式加速；再到 TechPowerUp GPU 数据库查 Tensor Core 数量与 FP16/INT8 算力，亲手验证"INT8 = FP16 × 2"
- **看引擎点名了谁**：vLLM 加载 AWQ/GPTQ 模型时启动日志会打印 marlin 字样，确认走反量化 kernel；启动参数里的 attention backend（如 FLASHINFER / FLASH_ATTN）就是在选注意力 kernel 库，换 backend 重测同一组 prompt，速度可能差一截
- **分列测速对账**：llama.cpp 跑 `llama-bench -p 8192 -n 128`，pp 列反映算力（有无 Tensor Core 立见），tg 列反映带宽；把无 TC 的 P40（官方 7B：Prefill 1000+、Decode 50+）与有 DP4A 的 P102 代入对照，可自行复现上面那张表
