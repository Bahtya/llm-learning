## 一个家用厨房，一个中央厨房

在本地跑同一个模型，有两条完全不同的路径：一条是下载一个几 GB 的文件、双击图标就开始对话；另一条是把一张（或几张）显卡变成一个 HTTP 服务，同时给几十路请求供餐。背后是两类软件，UP 主一句话点过分工："SGLang 是当前非常火的一个框架，llama.cpp 是当前大家最主要在端侧用的框架。"推理框架（inference framework）因此分两派：**llama.cpp** 系是家用厨房，一个人吃，开火就做；**vLLM / SGLang / TensorRT-LLM** 系是中央厨房，要管排队、流水线和保温柜。

分野落在三个维度上：

- **吃什么文件**：llama.cpp 系吃 **GGUF**，单文件自带量化档位，拷走就能跑（档位本身见 [INT8/INT4 与 GGUF 档位](#/v2/03)）；vLLM 一系吃 **safetensors** 裸权重（raw weights），即 Hugging Face 仓库里的原始精度权重，量化由框架加载时自己决定。
- **怎么交互**：桌面 GUI 给你一个对话框；服务级框架给你一个 API 端口。
- **优化目标**：前者榨单并发的输出速度，后者榨总吞吐（throughput）——两个数的区别见 [先会看表](#/v3/01)，并发怎么撑起来见 [并发与批处理](#/v3/04)。

## 流派一：llama.cpp 系——端侧、桌面 GUI 与一把尺子

这一派的护城河不是单点速度，而是生态（ecosystem）。GGUF 由 llama.cpp 主要维护，UP 主的类比是"GGUF 之于本地 AI，就像英伟达之于本地 AI 显卡——生态位一样"。它还有一批以它为底座的桌面前端（LM Studio 桌面 GUI、Ollama 一键运行器），三平台通用，"一行代码不用写，连 Linux 都不用装"；同底座的 Unsloth 则是微调加速库（可导出 GGUF 对接 llama.cpp），不算桌面前端。

> **案例（视频出处：BV1GtbL63Ekt）** 千问 27B 发布才 20 多天，社区就有超过 1000 个量化/魔改/后训练变体；而"本地目前最强"的 Kimi K3 只有 40 多个——合计上千个，量级差 25 倍。UP 主据此给入手顺序：先选 llama.cpp 底座的桌面前端，用 8G 显卡加"回落一部分到内存"的混合推理把模型跑起来——先测智力，再谈速度。

它还有个隐藏身份：**量卡片的尺子**——测显卡时引用 llama.cpp 官方/社区固定设置的数据做横向对比。

> **案例（视频出处：BV1E5426eE5X）** 十张百元卡的点评全程挂着一个 llama.cpp 基准：70~80 元的矿卡 P104，社区换算下 prefill 约 700 tok/s、decode 约 45 tok/s（两阶段见 [Prefill 与 Decode](#/v1/07)）。UP 主提醒口径：用的是很老的 Llama 3 7B，只能做相对参考——数字怎么读，见 [先会看表](#/v3/01)。

## 流派二：vLLM、SGLang、TensorRT-LLM——服务级

这一派把 GPU 当机房设备：吃 safetensors，对 KV 空间做分页管理（见 [vLLM 与 PagedAttention](#/v3/03)），用 CUDA Graph 消发射开销、也占一块显存（图机制见 [CUDA Graph](#/v3/05)；CUDA 本身是英伟达显卡软件生态，见 [CUDA vs ROCm](#/v3/09)）。代价是门槛：UP 主明确劝新手"不要太早进入 vLLM、SGLang"——要 Linux、要编译，"光是编译你可能都会遇到一大堆问题"。

另一道门槛是**架构支持**。

> **案例（视频出处：BV1E5426eE5X）** 3060 12G 的最大优势是安培（Ampere，30 系那一代，SM86 是其架构代号，见 v4/04）："现有的 vLLM、SGLang、ComfyUI 全都原生支持，不需要魔改"（ComfyUI 是文生图工作流工具）；反例是 V100——如今的新版（V1 引擎）不再官方支持 Volta（V100），UP 主的说法是"从来没有被 vLLM 类高性能框架正式官方支持过"（引擎层面曾短暂支持、V1 起移除；UP 主口播强调的是从未成为一等公民），全靠社区开源贡献续命，CUDA 也停在 12。选框架前先核对自己卡的代际（见 [架构代际](#/v4/04)）。

两个流派的功能边界也在互相渗透：UP 主测投机解码时，同一套实验在两边框架里各跑一遍。

> **案例（视频出处：BV1qGh56JEj2）** 同一组投机解码方案（MTP/dFlash/DSpark）分别在 SGLang 和 llama.cpp 上实测，结论接近；差别在细节——llama.cpp 的甜点区间是一次推测 2/3/4 个 token。机制本身见 [投机解码](#/v3/06)。

## 两朵旁支：MLX 与 ComfyUI

**MLX** 是苹果的框架底座。UP 主在 Mac 上更推荐 MLX 底座的应用——它吃的是统一内存架构（CPU/GPU 共享一片内存，见 [统一内存与 offloading](#/v4/08)），和插独立显卡的机器不是一个玩法。

**ComfyUI** 则根本不是 LLM 框架：它是文生图这类 AIGC（AI-Generated Content，人工智能生成内容）的节点式工作流工具，只是与推理框架共享同一张显卡、同一套量化生态（比如直接加载 INT8 模型）。于是"算力强但显存小"的卡就被派去画图——千问 27B 塞不下，文生图反而正好。

## 什么时候用哪个

| 场景 | 选谁 | 一句话理由 |
| --- | --- | --- |
| 个人电脑马上能聊、先测智力 | llama.cpp 底座桌面 GUI | 零代码、三平台、GGUF 下载即用 |
| 显存不够，想用内存凑 | llama.cpp 混合推理 | 支持层回落内存 |
| Mac | MLX 底座应用 | 统一内存的原生底座 |
| 给多人/多 Agent 提供 API | vLLM / SGLang | 高吞吐、并发调度 |
| NVIDIA 新卡追极致优化 | TensorRT-LLM | 厂商自营，绑定新架构 |
| 显卡改行做文生图 | ComfyUI | AIGC 工作流生态 |

一句话收束：先想清楚自己是**用模型**还是**运营模型**。用，从 llama.cpp 系进；运营，再上服务级框架——顺序反过来，你会在编译报错里耗掉一个周末，还没跟模型说上第一句话。

## 怎么验证

- **对照两种文件**：打开任一模型的 Hugging Face 主仓库，根目录是 `model-0000X-of-*.safetensors`；再搜它的 `*-GGUF` 镜像仓，文件名里直接带 `Q4_K_M` 这类档位字样。两个目录就是两个流派各自的口粮。
- **流派一跑通**：装 Ollama 后执行 `ollama run qwen2.5:7b`，或用 LM Studio 图形界面下载模型——全程不需要命令行以外的东西。
- **流派二跑通**：`pip install vllm`，然后 `vllm serve <模型名>`，另开终端 `curl` 一次 `/v1/chat/completions`。看启动日志：它会打印 KV 缓存分页和 `GPU memory utilization` 这类服务级字段。
- **查支持矩阵**：到 vLLM 官方文档的 supported hardware 页面核对手里卡的代际；老卡再确认 CUDA 版本上限。
- **用同一把尺子量两派**：同一模型、同一 prompt，llama.cpp 用 `llama-bench`，vLLM 读返回体里的吞吐字段——注意两个数字口径不同（见 [先会看表](#/v3/01)）。
