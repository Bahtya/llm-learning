## CUDA Graph：消掉发射开销

先补上本章需要的前置概念：**kernel（内核）**是一段在 GPU 上整段执行的函数。一次矩阵乘是一个 kernel；把 FP8 权重先反量化成 FP16、再接着做矩阵乘，也可以打包成一个 kernel。跑一次前向传播，就是把几百个这样的 kernel 按固定顺序执行一遍。

问题出在"谁在指挥"。

### 直觉：大厨与服务员

GPU 是手速极快的大厨，CPU 是服务员。每上一道菜，服务员都要单独递一张单子：报菜名（kernel 入口地址）、报配料（参数）、报取餐口（显存地址）。递单本身有固定耗时，叫**发射开销（launch overhead）**，量级在每次几微秒（公开量级，视频未给实测值）。

Prefill 阶段不在乎：每个 kernel 都是大菜，一算几毫秒，递单的几微秒九牛一毛（两阶段分工见 [Prefill 与 Decode](#/v1/07)）。Decode 阶段正相反：每吐一个 token 都要完整跑一遍前向，而此时 batch 小、每个 kernel 只做"矩阵乘向量"，GPU 微秒级就算完，然后停下来等下一张单子。算一笔账：双 2080Ti 跑 27B 的方案单并发实测 100 tok/s（含 MTP 加速，见 [案例通读](#/v5/01)），均摊每个 token 只有 10 ms 预算；假设前向发射 500 个 kernel、每次 5 μs，光递单就是 2.5 ms，四分之一时间 GPU 在干等。占比是估算，用来给数量级，不是视频实测。

### 原理：录一遍，整图回放

**CUDA Graph**（CUDA 图；CUDA 是英伟达显卡软件生态，见 [CUDA vs ROCm](#/v3/09)）的思路是"录菜谱"：第一次按老办法逐个发射，同时把这一整串 kernel 连同参数、显存地址**捕获（capture）**成一张图；之后每个 token 只发一条**回放（replay）**指令，GPU 照录像自动跑完全程。几百次 CPU→GPU 往返压成一次，省下的就是上面算的递单时间。

代价是显存。回放要成立，每次执行的地址必须一模一样，所以引擎建图时就得把 kernel 用的**工作区（workspace）**分配好并钉死，还要给单并发、2 并发、4 并发……每种批次档位各录一张图。这块显存从此被划走，不能再让给 [KV 缓存](#/v1/05)或更长上下文，记账时算进缓冲区一本（见 [显存三本账](#/v4/02)）。另外形状必须可预测：序列长度或并发数超出建图档位，就得补齐到固定长度（padding）凑档，或者退回逐个发射的老路。

> **案例（视频出处：BV1E5426eE5X）**
> UP 主盘点百元卡时算过这笔账：CMP 90HX（英伟达挖矿计算卡，见[显卡市场生存指南](#/v4/10)）单卡只有 10G 显存，要在 vLLM、SGLang 这类高性能框架里跑 27B 的低精度（FP4 级）权重"至少三张显卡"；就算凑满四张也才 40G，还要再扣掉"每张显卡当中的一些缓冲空间、CUDA Graph、然后运行时"，**能用的显存空间会更小**。卡越小、卡越多，被图和运行时扣走的那块就越疼。

> **案例（视频出处：BV14yT46kE5T）**
> 再看"省时间"省在哪。Marlin kernel 值得单独写一个，是因为它把"反量化 + 矩阵乘"合进一个 kernel，一次发射干完两层活；CUDA Graph 是同一思想的另一端：不动 kernel 内部，专消 kernel 之间的空白。UP 主的 2080Ti 运行时项目一个多月迭代到 v0.1.12（版本号为该期视频时点，项目仍在迭代）、收获 300 star（GitHub 上的收藏数），靠的就是这类细账。

### 什么时候开

| 场景 | 建议 | 原因 |
| --- | --- | --- |
| vLLM/SGLang 起服务、decode 为主 | 默认开 | 小 kernel 是大头，整图回放收益最大 |
| 显存极限紧张（小卡、多卡） | 考虑关 | 每张卡都被扣一块，可能直接决定跑不跑得下 |
| 长输入短输出、Prefill 为主 | 开关差别不大 | kernel 大而少，发射占比本就低 |
| 调试、并发/长度频繁变化 | 关 | 回放要求形状固定，动态形状处处碰壁 |

取舍是用显存换延迟。vLLM 的开关是 `--enforce-eager`（eager 模式 = 退回逐个发射），SGLang 是 `--disable-cuda-graph`。CUDA Graph 是 CUDA 生态的机制，这套"引擎优化绑定硬件生态"的话题，见 [CUDA vs ROCm](#/v3/09)；kernel 内部靠什么快起来，见 [内核与算子](#/v3/07)。

## 怎么验证

- **看启动日志**：`vllm serve` 启动时会打印 `Capturing CUDA graphs`（按批次档位逐张建图）；此刻另开终端跑 `nvidia-smi`，显存会跳涨一块，那就是录图的成本。
- **对比速度**：同一模型、batch=1（为什么单并发最真实，见 [先会看表](#/v3/01)），带与不带 `--enforce-eager` 各跑同一段提示词，记输出速度（tok/s 两种口径别混）。
- **算账**：把两次 tok/s 各自换算成每 token 毫秒数，差值就是被发射开销吃掉的部分；再和"500 次 × 5 μs = 2.5 ms"的估算对一下数量级。
- **看显存差**：两种启动各自稳定后用 `nvidia-smi` 记显存读数，差值≈各档位图的工作区总和。这笔钱够不够多放一路并发（每路一份 KV），就是开不开的判据。
