## 一条车道一股流量：lane 与代际带宽表

PCIe（Peripheral Component Interconnect Express）是显卡通往 CPU 的常规公路。它的基本单位是 lane（通道），即一组收发对线；x1、x4、x8、x16 表示并排几股。账只有一个公式：**单 lane 速率 × lane 数**，两个变量都要问清，缺一个都会买错卡。

| 代际 | 单 lane 单向 | x16 合计 |
| --- | --- | --- |
| PCIe 1.0 | 250 MB/s | 4 GB/s |
| PCIe 2.0 | 500 MB/s | 8 GB/s |
| PCIe 3.0 | 约 1 GB/s | 约 16 GB/s |
| PCIe 4.0 | 约 2 GB/s | 约 32 GB/s |
| PCIe 5.0 | 约 4 GB/s | 约 64 GB/s |

先记住两个量级：**PCIe 1.0 x4 约 1 GB/s**（后文的极端案例），PCIe 3.0 x16 约 16 GB/s（老卡标配）。

## 车道从哪里引出来：CPU 直连与南桥 PCH

车道不是凭空长的，起点是 CPU 里的 root complex（根复合体）。**直连 CPU** 的 lane 独享带宽、延迟最低；挂在**南桥**（PCH，Platform Controller Hub，芯片组）上的插槽，要先在南桥汇合、再挤一条上行链路回 CPU。消费级主板通常只有一条 x16 直连，其余插槽和 M.2 口都在南桥后面——M.2 的本质就是 PCIe 通道，所以能转出 x1/x4 来挂卡。服务器平台相反：EPYC 7002/7003 可以给到 128 条 PCIe 4.0，至强 W 也有多条 x16 直连。

## 同一个 root 才好抄近道：P2P、bifurcation、riser、PLX

双卡推理想要 P2P（peer-to-peer）：两张卡经 PCIe 直接互访对方显存，不绕 CPU。能不能走通看拓扑（topology）：

- **bifurcation（通道拆分）**：BIOS 把一条 x16 拆成 x8+x8，两卡仍在同一 root complex 下，P2P 可用；
- **riser（转接卡）**：只挪位置，不生带宽；
- **PLX switch**（PCIe Switch 拆分卡，如 PEX88096）：用交换芯片一分多，代价是多一跳。

> **案例（视频出处：BV1Y2LX61EjQ）** 同样两张 2080Ti 22G 跑 27B 张量并行：服务器平台 x16 直连，decode 基本无损、prefill 仍受带宽影响；家用主板拆成 x8+x8（同一 root、可 P2P），decode 只慢 3%~5%、prefill 明显变慢；若一张 x16 直连、另一张走南桥 x4，两头都掉——这条 UP 主明说是推测值，未实测。

> **案例（视频出处：BV1hLtG6ZE5M）** 反例：3080 20G 单卡很强，却不支持 P2P 点对点拷贝，实测双卡并联未必快过两张 V100 或两张 2080Ti；换 PLX 拆分卡，短板反而被放大。

> **案例（视频出处：BV12ZEN6CEho）** 一台 M720q 迷你主机塞下三张卡的接法：riser 把通道分成一路 x8（直连 CPU）和一路 x4（走南桥桥接），M.2 再转出 PCIe 3.0 x1；两张 2080Ti 各占 x4 与 x1、靠 NVLink 互联实现 P2P，省下的 x8 引出接第三张卡。所谓"全家桶"，就是把每条 lane 的来路数清楚。

## NVLink：不占车道的专线

[双卡张量并行](#/v4/06) 每层都要做 all-reduce，通信全部压在卡间链路上。NVLink 是 NVIDIA 的卡间直连总线，不占 PCIe lane：2080Ti 上的 NVLink 2.0 有两条链路、双向共约 100 GB/s，约为 PCIe 3.0 x16 的 6 倍。2080Ti 22G 拿五星（UP 主天梯五星，见[显卡天梯](#/v5/04)），理由正是这个桥接器——双卡拼出 44G 显存，算力"1+1 远大于一"。AMD 的对应物叫 xGMI（AMD 版的 NVLink 卡间直连）；跨机的 ConnectX-7 网卡、USB4（本质是给 PCIe 做隧道的协议）属于同一条故事线，记住名字即可。

> **案例（视频出处：BV1Y2LX61EjQ）** 双 2080Ti 张量并行的 profiler 账（5G 多/129 次、80G、161MB、13 万次那笔细账记在 [TP vs PP](#/v4/06)）结论只有两句：prefill 对带宽敏感，decode 是小包高频、NVLink 在这阶段买的是延迟（两阶段口径见 [Prefill 与 Decode](#/v1/07)）。baseline：prefill 1700 tok/s，decode 不开 MTP 约 50 tok/s（裸 decode 口径见 [先会看表](#/v3/01)），开 MTP 后 100（MTP 见 [投机解码](#/v3/06)），且强调这是最高速度、不保证稳定复现。

## 极限压测：PCIe 1.0 x4 照样能赚

> **案例（视频出处：BV1dx3Q6iEbZ）** 矿卡 CMP 170HX 补电路飞线后只剩 PCIe 1.0 x4（约 1 GB/s）：双卡流水线并行下 prefill 快 72%、decode 不劣化；MI250 快 60%、2080 快 50%。原理在 [v4/06](#/v4/06)：PP 卡间每次只传分界层的 hidden state，prefill 一次几 MB 到几十 MB，decode 更只有几 KB——带宽再烂也拖不垮 [带宽决定 Decode](#/v4/03) 那笔账。

## 怎么验证

- 看协商结果：`sudo lspci -vvv -s <设备地址> | grep LnkSta`，`Width x16` 是 lane 数，`8GT/s` 对应 3.0、`16GT/s` 对应 4.0；`nvidia-smi -q` 里也有 GPU Link Info 一节。
- 看拓扑：`nvidia-smi topo -m`，交叉格是 `NV#`（NVLink 几条链路）、`PIX`（同一 switch 内，P2P 最快）、`PHB`（过 root complex）、`SYS`（跨 CPU，最差）。
- 算一笔账：600 GB/s 显存带宽的卡若协商成 PCIe 3.0 x4（约 4 GB/s），只相当于显存的约 1/150——这就是 offload 慢、双卡都怕通信的原因。
- 实测 P2P：编译 cuda-samples 的 `p2pBandwidthLatencyTest`，看 P2P 是否启用、双向带宽多少。
- 动手对比：BIOS 开 `Above 4G Decoding` 并把 bifurcation 设为 x8x8 再插双卡；llama.cpp 用 `--split-mode layer`（即流水线并行）对比 `row`（张量并行），观察 prefill 和 decode 谁先掉，对应上文两条结论。
