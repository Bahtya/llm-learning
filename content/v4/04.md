## 一条时间线，只回答两个问题

把 GPU 想成一家只做一道菜的餐厅，这道菜叫矩阵乘法（matrix multiply）：大模型推理的绝大部分算力都花在它身上。所谓架构代际（architecture generation），不是"锅更贵了"，而是做这道菜的方式换代了——从 Volta 开始，厨房里多了一台专做矩阵的机器：张量核心（Tensor Core）。此后每一代都在回答同一个问题：**这台专机一次能吞多小的数？**格子越小，一次吞得越多，算得越快。

所以读代际只要抓两件事：这一代新增了哪种精度的加速单元（决定算力账）；框架官方认不认这一代（决定折腾上限）。算力和带宽各卡哪个阶段，见[带宽决定 Decode、算力决定 Prefill](#/v4/03)。

### 六个站牌

| 代际 | SM 代号 | 代表卡 | 新增的关键能力 |
| --- | --- | --- | --- |
| Pascal | SM60/61 | P40、P100、P104 | 无 Tensor Core，只有 DP4A 整数融合算子（SM61 的 P4/P102/1080Ti 有，SM60 的 P100 没有） |
| Volta | SM70 | V100 | 第一代 Tensor Core |
| Turing | SM75 | 20 系（2080Ti） | 第二代 Tensor Core + INT8 矩阵加速 |
| Ampere | SM86 | 30 系（3080） | 第三代 Tensor Core + TF32 + 混合流水线 |
| Ada | SM89 | 40 系 | 原生 FP8 |
| Blackwell | SM100/120 | 50 系 | 原生 NVFP4 |

TF32、FP16、BF16 这些格子本身长什么样，去[浮点数从零讲起](#/v2/01)；FP8 与 NVFP4 在[FP8 与 NVFP4：更小的格子](#/v2/02)；Tensor Core 三代的指令细节在[内核与算子：快从哪里来](#/v3/07)。本章只回答：代际差怎么换算成钱和体验。

### Pascal：没有专机，24G 也快不起来

Pascal 是"显存很大、算不动"的典型：P40 有千元档唯一实用的 24G 显存，却没有 Tensor Core，矩阵只能靠普通 CUDA 核心硬算。Pascal 只有 DP4A 这条 INT8 融合算子指令（P4/P102/1080Ti 有），撑不起真正的矩阵运算——P100 这张专业卡连 DP4A 都没有。

> **案例（视频出处：BV1hLtG6ZE5M）**
> P40 跑 llama.cpp 官方 7B 基准：prefill 约 1000+ tok/s、decode 约 50+ tok/s，是八张推荐卡里最慢的一张——24G 显存救不了没有 Tensor Core 的算力。

> **案例（视频出处：BV1E5426eE5X）**
> P100 有 HBM2 显存、700GB/s 级带宽（门派之见[HBM vs GDDR：显存也分门派](#/v4/05)），是十张百元卡里带宽最高的一档，却因整代缺乏 INT8 加速，prefill 只有 700 多 tok/s，被 150 元的 P102（能上千）反超——带宽是瓶颈，不是唯一瓶颈。

### Volta → Turing → Ampere：专机三代

第一代 Tensor Core 让 V100 的 FP16 算力冲到约 130 TFLOPS（视频口播 130T；官方口径 PCIe 112T、SXM2 125T）、同模型短测 prefill 约 3000 tok/s（是 MI50 的三倍）；但它的 INT8 只有融合算子、做不了矩阵运算，本该翻倍的算力释放不出来，跑 ComfyUI 的 INT8 文生图甚至不如 FP16。第二代（Turing，SM75）补上 INT8 矩阵加速；第三代（Ampere，SM86）支持异步拷贝，把喂料和计算重叠。

Ampere 还改了流水线：SM86 前 FP32 浮点核心和 INT32 整数核心是分开的（一半算浮点、一半算整数），SM86 后整数核心兼算浮点，单精度翻倍。3080 物理核心规模没比 V100、2080Ti 大多少，单精度却接近 30 TFLOPS。

> **案例（视频出处：BV1hLtG6ZE5M）**
> 相同算力档位下，3080 20G 的 prefill 比 V100 和 2080Ti 高约 60%~70%，解码也快不少；反过来，笔记本魔改（把笔记本 GPU 芯片改造成桌面卡）的 3070 系半精度只有 70 多 T、INT8 约 150T，纸面不如 2080S，却因握着第三代 Tensor Core 实际推理更好——代际看的是指令，不是纸面 TFLOPS。

### Ada 与 Blackwell：格子继续变小，老卡照吃不误

Ada（40 系）首次原生 FP8，Blackwell（50 系）原生 NVFP4。于是有社区质疑："2080Ti 连 BF16 都不支持，怎么可能跑 FP8 权重？"这混淆了**存**和**算**：量化只改变权重的存储位宽，并不要求你以这个精度运算。weight-only 路线（W8A16：8 位权重、16 位激活值）在算之前先反量化回 FP16，所以 vLLM 的 quantization 文档硬件支持表里，图灵赫然在列、Volta 不在。

> **案例（视频出处：BV14yT46kE5T）**
> 20 系不支持 FP8 加速，但支持 INT8 加速，且 INT8 算力是 FP16 的两倍；vLLM 引擎里负责"FP8/FP4 权重反量化成 FP16 再算"的就是 Marlin kernel——FP8 权重不代表以 FP8 运算，它只描述模型的量化水平。

命名规则（W8A16/W8A8）见[权重与激活：W8A16 命名的世界](#/v2/04)，Marlin 的快慢账见[量化粒度与异常值：Marlin 为什么快](#/v2/05)。

### 2080Ti 站在哪一格

Turing SM75，二零系卡皇（卡皇=圈内对某一代最强卡的戏称）。有：第二代 Tensor Core、INT8 矩阵加速、卡间 NVLink 桥接器（双卡 22G 拼 44G，互联见[NVLink 与 PCIe 全家桶](#/v4/07)）。没有：BF16、FP8、FP4 的硬件加速单元，新格子的红利一个都吃不到——框架适配全靠社区，账在[CUDA vs ROCm：软件生态的账](#/v3/09)（图灵是 CUDA 13 仍支持的最低架构，真正停在 CUDA 12 的是 Volta/Pascal）；矿潮体质（体质=同型号芯片的个体好坏差异）问题在[显卡市场生存指南](#/v4/10)。

### 为什么老卡还能打

- **Decode 是搬权重，不是算。**Decode 是访存受限（memory-bound）的：每生成一个 token 都要把权重从显存过一遍，瓶颈在带宽不在算力，所以 Z100L 这种没有 Tensor Core 的卡，decode 靠两倍显存带宽"力大砖飞"，也有魔改卡约 90% 的解码性能。
- **权重吃新格子的红利，计算走老格子的路。**FP8/FP4/Q4 权重反量化后照跑（见[INT8/INT4 与 GGUF 档位](#/v2/03)），显存省了，计算还是熟悉的 FP16。
- **但 prefill 是算力问题，老卡真的吃亏。**V100 32G 就是反例：权重量化后"存得下"，却因缺 INT8 加速"算不过来"，32G 大显存反而尴尬。

## 怎么验证

- **查代际**：终端跑 `nvidia-smi --query-gpu=name,compute_cap --format=csv`，`compute_cap` 就是表里的 SM 代号——2080Ti 是 `7.5`、P40 是 `6.1`、V100 是 `7.0`、3090 是 `8.6`。或者用 Python：`torch.cuda.get_device_capability(0)`。
- **查加速单元**：到官方规格页查你那张卡的各精度 TOPS，自己验证"INT8 = FP16 × 2"对哪几代成立。
- **查框架支持**：打开 vLLM 文档的 Quantization 章节的硬件架构 support 表——搜 Turing 在不在列、Volta 缺不缺席，这就是"老卡能吃 FP8 权重"的文档证据。
- **实测算账**：用 llama.cpp 跑同一个模型、同一份 GGUF，记录 prefill（吞）和 decode（吐）两个数（读法见[先会看表：tok/s、吞吐与单并发](#/v3/01)），拿 P40 的 7B（prefill 1000+ / decode 50+）作参照线。
- **验证"存得下算不过来"**：按[显存三本账：权重+KV+缓冲](#/v4/02)算出 V100 32G 的权重账，确认装得下，再解释它为什么还是跑不快。
