## FP8 与 NVFP4：更小的格子

上一章把浮点数（floating point）拆成符号、指数、尾数三段（见 [浮点数从零讲起](#/v2/01)），这一章把位数砍到更低：FP8（8 位浮点）的位宽是 FP16 的一半，FP4（4 位浮点）再砍一半。落到权重存储上就是直接的显存减法：以视频里反复出现的 27B 模型为例，FP16 装下要 54G，FP8 只要 27G，FP4 只要 13.5G——同一张卡，装得下的模型翻倍再翻倍（位宽与显存的换算见 [INT8/INT4 与 GGUF 档位](#/v2/03)）。

但显存不是白省的：格子越小，数放得越"糙"。

### 数轴上只剩 256 个点

8 位一共只有 256 种组合，所以 FP8 能表示的数只有 256 个（忽略 NaN/Inf 等特殊编码）；FP4 只有 16 个；FP16 有 65536 个。量化（quantization）做的事，就是在连续的数轴上立起一排稀疏的格子点，再把原数四舍五入到最近的格子上——格子越稀，误差越大。

格子怎么摆，取决于这 8 位怎么在指数和尾数之间分账，这就是动态范围与精度的取舍：

- **指数位**决定动态范围（dynamic range）：能表示的最大/最小数，格子的覆盖半径
- **尾数位**决定精度（precision）：相邻格子的间距，四舍五入时的误差大小

FP8 有两个标准变体，就是两种分法：

| 格式 | 指数 | 尾数 | 最大值约 | 常见分工 |
| --- | --- | --- | --- | --- |
| E4M3 | 4 | 3 | ±448 | 权重与前向计算，默认选它 |
| E5M2 | 5 | 2 | ±57344 | 数值波动大、要装得下大数的场合 |

预算就 8 位：指数多一位，尾数就得少一位。E4M3 格子密、范围窄，适合数值扎堆的权重；E5M2 范围宽、格子稀。FP4 更极端——E2M1 只剩 16 个点，格距粗到没法直接用，于是 NVIDIA 给 NVFP4 在外面套了两层缩放因子（scale）：每 16 个数共享一个 FP8 缩放值，再叠一层全张量级缩放（整组数共用一个 scale，见 [量化粒度与异常值](#/v2/05)），把动态范围找补回来。本质是"格子密不了，就把格子挪到数值最密的地方"。

### 谁原生支持：Ada 才有 FP8，Blackwell 才有 NVFP4

原生支持指 Tensor Core（张量核心）里真有这种格子的电路，一个周期直接算完。FP8 的硬件起点是 Ada（40 系；此处指消费卡，数据中心的 Hopper 更早），NVFP4 是 Blackwell（50 系），完整代际表见 [架构代际：从 Pascal 到 Blackwell](#/v4/04)。

| 硬件 | FP8 浮点 | FP4 浮点 | 备注 |
| --- | --- | --- | --- |
| Blackwell（50 系） | 支持 | 原生 | DGX Spark 跑 NVFP4 换速度 |
| Ada（40 系） | 原生 | 无 | |
| 图灵 Turing（20 系） | 软件模拟 | 软件模拟 | 另有 INT8 加速，算力比 FP16 翻倍 |
| 苹果 M3/M4 | 模拟且无加速 | 无 | 低精度矩阵路径未开放，需软件模拟。M5 起原生的是低精度矩阵运算（FP16/INT8）；FP8 苹果全系仍未支持 |
| AMD AI Max 395（RDNA3.5） | 无 | 无 | 整数低精度仍支持 |

> **案例（视频出处：BV1otY26LE8w）**
> 同一期横评里的三种待遇：DGX Spark 是 Blackwell，FP4/FP8 超低精度浮点都支持，UP 主的建议是"不在意质量的话，直接跑 NVFP4 量化模型换推理性能"；AI Max 395 属于 RDNA3.5，FP8 浮点运算不支持、整数级别还可以；苹果的低精度矩阵路径在 M3/M4 上未开放，只能靠融合算子（把几步运算合并成一步的写法，见[内核与算子](#/v3/07)）软件模拟，要等到 M5 这一代才原生支持——M5 是"实打实的四倍级低精度运算"，预填充（Prefill，见 [Prefill 与 Decode：吞字与吐字](#/v1/07)）随之暴涨。

### 老卡的"支持"：存的是 FP8，算的是 FP16

软件模拟最常见的形态：权重以 FP8/FP4 位宽**存放**（省显存、省带宽），计算前先反量化（dequantize）回 FP16 再**运算**。于是有句要钉在墙上的话：**支持 FP8 权重 ≠ 以 FP8 运算**——前者只是存储格式，后者需要硬件电路。老卡跑 FP8 权重，赚的是搬运减半，不是算力翻倍；想吃到翻倍算力得走 INT8 路线（见 [内核与算子：快从哪里来](#/v3/07)）。这条反量化路线在 vLLM 里由 Marlin kernel 执行（W8A16 命名规则见 [权重与激活](#/v2/04)，kernel 本身的戏份见 [量化粒度与异常值](#/v2/05)，省下的显存拿去换什么、质量上要还什么债见 [量化的代价](#/v2/06)）。

图灵跑 FP8 靠的就是反量化——那场"你连 BF16 都不支持"的社区质疑与 UP 主的翻案（硬件支持表里有图灵、没 Volta），定点记在 [权重与激活](#/v2/04)。

## 怎么验证

- **查支持表**：vLLM 官方文档 quantization 章节，按硬件架构（Volta/Turing/Ada/Blackwell）列出每种量化格式的支持方式
- **查自己的卡**：

```bash
python -c "import torch; print(torch.cuda.get_device_capability())"
# (7,5)=图灵  (8,9)=Ada  (12,0)=50 系 Blackwell
```

- **数格子、算上限**：

```python
import torch
2**8, 2**4                            # 256, 16：FP8/FP4 各只有这么多格点
torch.finfo(torch.float8_e4m3fn).max  # 448.0
torch.finfo(torch.float8_e5m2).max    # 57344.0
```

- **看显存**：同一个 27B 模型分别以 FP16 与 FP8 加载，用 `nvidia-smi` 读显存，权重账应从约 54G 掉到约 27G，恰好减半；换 FP4 再减半
